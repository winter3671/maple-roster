# 거래 내역 CSV 내보내기

## 사용 방법

거래 내역에서 시작일·종료일·캐릭터를 선택하고 **조회**를 누른 뒤 **CSV 내보내기**를 누른다. 운영체제 저장 대화상자에서 `.csv` 파일의 위치와 이름을 지정한다. 성공하면 적용 기간·거래 수·저장 경로를 표시한다. 취소하면 파일을 저장하지 않는다.

아직 조회를 누르지 않은 입력값은 내보내기에 적용하지 않는다. 마지막으로 조회한 조건으로 백엔드의 거래 내역을 다시 읽고, 저장 대화상자를 열기 직전에 확정한 데이터를 저장한다. 내보내는 동안 중복 클릭과 필터 변경을 막는다. 전체 캐릭터를 선택하면 숨긴 캐릭터의 거래도 포함한다. 기간에는 시작일과 종료일을 모두 포함하며 기록의 수익·지출 반영일을 기준으로 조회한다.

사냥·결정석·드랍 판매가 만든 실제 거래만 내보낸다. 미판매 아이템의 예상 가치, 캐릭터 프로필, OCID, API 키와 원본 API 응답은 포함하지 않는다. 내보내기는 장부를 변경하지 않는다. 거래가 없으면 헤더만 있는 CSV를 저장한다.

## 열과 금액

| 열                | 내용                                              |
| ----------------- | ------------------------------------------------- |
| 날짜              | 수익·지출 반영일, KST `YYYY-MM-DD`                |
| 캐릭터            | 현재 캐릭터명                                     |
| 서버              | 기록에 저장된 서버                                |
| 분류              | 사냥 메소, 사냥 비용, 결정석 수익, 드랍 판매      |
| 구분              | 수입 또는 지출                                    |
| 금액(메소)        | 원래 거래의 양수 정수 금액                        |
| 순수익 변동(메소) | 수입은 양수, 지출은 음수로 기록한 금액            |
| 거래 ID           | 장부 거래를 식별하는 ID                           |
| 원본 기록 ID      | 사냥 회차·결정석 정산·드랍 판매 중 연결된 기록 ID |

거래 목록과 같은 순서로 내보내며 별도의 합계 행을 넣지 않는다. 순수익 변동 열을 합산하면 조회 범위의 순수익을 계산할 수 있다. 금액에는 천 단위 쉼표와 ‘메소’ 단위를 붙이지 않고 원래 정수를 그대로 쓴다.

## 엑셀과 파일 형식

- UTF-8 BOM을 넣어 한글을 인식하기 쉽게 하고 행 구분에는 CRLF를 사용한다.
- 모든 필드를 큰따옴표로 감싸고 내부 큰따옴표를 두 번 쓴다. 쉼표·따옴표·줄바꿈을 필드 안에 보존한다.
- 사용자 문자열이 `=`, `+`, `-`, `@` 등으로 시작해 수식으로 해석될 수 있으면 앞에 작은따옴표를 추가한다. 보호된 문자열은 파일에서 표시용 작은따옴표가 보일 수 있다. 앱이 생성한 음수 메소는 숫자 그대로 유지한다.
- CSV에는 열의 자료형 정보가 없다. 엑셀에서 15자리 초과 금액을 원래 자릿수대로 다루려면 CSV 가져오기에서 금액과 순수익 변동 열을 텍스트로 지정한다. 파일 자체는 `9007199254740991`까지 원래 안전 정수를 그대로 보존한다.
- 파일 한도는 50MB다. 초과하면 조회 기간이나 캐릭터 범위를 줄이라는 오류를 표시한다.
- 같은 폴더의 임시 파일을 먼저 완성한 뒤 최종 파일명으로 교체한다. 저장 실패 시 기존 파일을 유지하고 임시 파일을 정리한다. `.csv` 확장자만 허용한다.

CSV는 분석용 거래 목록이다. 장부 복원에는 캐릭터·프리셋·드랍 수량 등 전체 관계를 포함하는 [JSON 백업](backup.md)을 사용한다. CSV로 장부를 복원하는 기능은 제공하지 않는다.

## 구현과 검증

- `backend/domain/ledger-csv.ts`: BOM·열·금액·인용과 수식 문자열 보호
- `backend/modules/ledger/ledger.service.ts`: 조회 조건 검증과 거래 스냅샷
- `backend/files/atomic-text-file.ts`: JSON 백업과 CSV가 공유하는 파일 저장
- `desktop/main/ipc/ledger.handlers.ts`: 저장 대화상자·허용된 IPC 호출
- `frontend/features/ledger/LedgerPage.tsx`: 내보내기 버튼·상태·오류·적용 조건 안내

테스트는 BOM·CRLF, 쉼표·따옴표·줄바꿈, 수식 문자열, 음수 지출과 큰 정수, 빈 헤더, 모든 거래 분류·원본 ID, 기간·캐릭터·숨김 필터, 잘못된 조회 조건과 저장 실패를 확인했다. 격리 Electron 테스트에서는 실제 파일·IPC·화면으로 적용 전 입력값과 적용 후 필터의 차이, 저장·취소·잘못된 확장자·빈 조회 결과와 장부 보존을 확인했다. 운영체제 저장 대화상자의 반환 경로는 테스트용 임시 파일로 지정했다.
