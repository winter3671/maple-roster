# 진단 로그

설정 → 문제 진단 → 진단 로그 저장에서 최근 진단 기록을 JSON 파일로 저장한다. 자동 전송은 하지 않는다. 장부 JSON 백업과는 별도 기능이다.

## 기록 항목

- 앱 시작·정상 종료·실행 실패와 앱 버전
- IPC 요청 실패: 허용한 작업 이름, 오류 코드, 처리 시간
- API 일괄 조회의 실패·미처리: 오류 코드별 개수
- 2초 이상 걸린 요청: 작업 이름과 처리 시간
- 자동 백업 실패와 업데이트 실패 단계
- 화면 로딩 실패, 처리되지 않은 화면 오류, 화면 프로세스 중단·응답 없음

진단 파일에는 생성 시각, 현재 앱·Electron·Node 버전, 운영체제 종류도 포함한다. API 키, OCID, 캐릭터 이름, 장부 금액·메모, 입력·응답 본문, 원본 오류 메시지·스택, 내부 파일 경로는 기록하지 않는다. 자유 문자열을 마스킹하는 방식 대신 허용된 항목만 새 객체로 구성한다. 일부 실패의 메시지는 기록하지 않고 코드와 개수만 남긴다.

정상적인 빠른 요청과 상태 주기 조회는 기록하지 않는다. 화면 오류 보고는 창마다 분당 5건으로 제한한다. 오류가 급증할 때 쓰기 대기열은 최대 64건이며 초과한 수는 설정에서 확인할 수 있다.

## 저장 및 성능

`userData/logs`에 `diagnostics.jsonl`, `diagnostics.1.jsonl`, `diagnostics.2.jsonl`을 유지한다. 파일당 최대 512KiB이며 오래된 파일부터 교체하므로 관리 대상 로그는 최대 1.5MiB다. 외부에서 파일을 직접 변경한 경우에는 이 제한을 보장하지 않는다.

쓰기와 파일 회전은 비동기로 직렬 처리한다. 로그 쓰기 실패는 사용자 요청의 성공·실패 결과를 바꾸지 않는다. 설정에 로그 저장 문제를 표시하며 다음 기록에서 다시 저장을 시도한다. 정상 종료 시 최대 1.5초 동안 대기열을 비운다. 강제 종료·전원 차단 직전의 대기 기록은 남지 않을 수 있다.

공유 파일을 저장할 때도 기존 로그의 각 항목을 다시 검증하고, 파일당 읽기 크기를 제한한다. 알 수 없는 항목과 잘못된 JSON은 공유하지 않는다. 내보내기는 로그 쓰기·회전과 직렬 처리하며, 저장 창 취소는 성공 알림 없이 끝난다.

## 검증

`diagnostics.test.ts`와 `diagnostics-ipc.test.ts`에서 민감한 테스트 문자열 제외, 코드 허용 목록, 변조된 로그 재검증, 파일 크기·3개 순환, 대기열 제한, 쓰기·내보내기 실패 복구, 일부 실패 집계, IPC 프레임 검사와 보고 횟수 제한을 검증한다.

실제 Electron 검증은 별도 임시 장부를 사용한다. 설정의 저장 버튼으로 내보낸 파일, 파일 선택 취소, 원본 입력·오류 내용 제외, 화면 오류 보고와 정상 종료 기록을 확인한다. 사용자 장부는 사용하지 않는다.
