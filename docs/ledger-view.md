# 거래 내역의 수익 묶음과 지출

기간·캐릭터 조회 조건에 맞는 수입은 **보스 수익**, **사냥 수익**, **직접 수익** 세 묶음으로 표시한다. 여러 날짜·캐릭터를 조회하면 해당 조건 전체를 합산하며 캐릭터 필터로 한 캐릭터의 합계를 확인할 수 있다.

- 보스 수익: 결정 수입과 보스에서 획득한 드랍의 실제 판매 수익
- 사냥 수익: 직접 획득 메소와 사냥에서 획득한 드랍의 실제 판매 수익

각 묶음에는 금액과 원본 수입 건수를 표시한다. 수입이 없는 묶음도 0으로 표시하며 지출은 수익에서 차감하지 않는다. 상단 순수익 요약에서 전체 수입과 지출의 차이를 확인한다. 지출 내역은 날짜·캐릭터·분류·금액을 개별 행으로 표시하고 날짜 순서를 유지한다. 기존 사냥 비용과 지출 거래를 보존한다.

드랍 수익은 판매 기록의 획득 묶음을 조회하여 보스·사냥을 구분한다. 결정은 장부 반영일, 사냥 메소와 비용은 사냥 날짜, 드랍은 실제 판매일로 필터링한다. 미판매 예상 금액은 포함하지 않는다. 판매 수정·취소나 반영일 수정 후 새로고침하면 합계에 반영한다.

표시만 묶으며 DB의 거래를 병합하거나 삭제하지 않는다. 보스·사냥 수입의 수정·취소는 원본 장부에서 진행한다. 직접 지출은 거래 내역에서 수정·삭제한다. JSON 백업은 기존 개별 거래를 유지하고 CSV 내보내기도 조회 조건에 맞는 수입·지출 원본 거래 전체를 저장한다. 대시보드는 직접 지출 분류를 추가하고 순수익·캐릭터별·날짜별 집계에 반영한다.

테스트에서는 결정·보스 드랍·사냥 드랍의 분류, 합계와 전체 수입의 일치, 지출 제외, 판매일 필터와 판매 취소 후 합계를 확인한다. Electron 임시 장부에서 결정 12개와 보스 드랍을 보스 수익 하나로, 사냥 메소와 드랍을 사냥 수익 하나로 표시하고 지출은 개별 행으로 유지하는 동작을 확인했다.

## 직접 지출

**지출 추가**에서 날짜·캐릭터·분류·금액·메모를 입력한다. 분류는 장비 구매·강화·큐브·아이템 구매·기타이며 API로 가져오는 기록이 아니다. 금액은 1 메소 이상 안전한 정수 범위까지, 날짜는 오늘(KST)까지, 메모는 500자까지 받는다. 금액 입력 아래에는 억·만 단위 안내를 표시한다.

지출 목록의 **수정**으로 모든 입력값을 변경한다. **삭제**는 날짜·캐릭터·금액을 확인한 뒤 적용한다. 같은 캐릭터의 서버가 변경되어도 과거 지출의 기록 서버는 유지한다. 다른 캐릭터로 옮기면 해당 캐릭터의 현재 서버를 기록한다. 지출이 연결된 캐릭터는 해당 기록을 먼저 정리해야 삭제할 수 있다.

저장은 지출 원본과 거래를 하나의 트랜잭션으로 처리한다. 같은 저장 요청의 재시도는 한 번만 기록하고, 수정은 거래 ID를 유지하며 삭제는 대응 거래도 제거한다. 현재 조회 조건 밖에 저장한 경우 안내하고 조회 기간·캐릭터를 바꾸어 확인한다. 기존 사냥 비용은 유지하며 사냥 장부에서 관리한다.

직접 지출은 세 수익 묶음에 포함하지 않고 상단 지출·순수익 및 대시보드에 반영한다. CSV는 분류·메모·원본 ID를 포함하며 메모의 수식 주입을 방지한다. 수동·자동 JSON 백업 모두 직접 지출을 포함한다. 이전 DB 7·8·9 백업도 빈 직접 지출 목록으로 변환해 복원한다.

## 직접 수익과 입력 영역

조회 조건과 실제 수입·지출·순수익 사이의 **거래 기록** 영역에 **수익 추가**, **지출 추가** 버튼을 둔다. 입력 폼은 버튼 바로 아래에 표시한다. 아래 **수익·지출 내역**에서 직접 수익과 지출을 개별 행으로 확인하고 수정·삭제한다.

직접 수익은 캐릭터·날짜·분류·메소 금액·메모를 입력한다. 분류는 아이템 판매·메소 수령·이벤트·기타다. 금액 아래에는 억·만 단위 안내를 표시한다. 보스·사냥에서 이미 반영한 수입은 중복 입력하지 않는다. 입력 날짜 기준으로 집계하고 대시보드에도 별도 분류로 표시한다. 입력 검증, 저장 재시도 중복 방지, 서버 보존, 캐릭터 삭제 보호는 직접 지출과 같다. CSV와 수동·자동 백업에 포함하며 15번 이전 백업은 빈 직접 수익 목록으로 복원한다.

## 상세 내역 페이지

수익·지출 상세 내역은 직접 수익과 모든 지출(이전 사냥 비용 포함)을 50건씩 조회한다. 보스·사냥 자동 수입은 기존처럼 수익 묶음에만 표시한다. 날짜 내림차순, 생성 시각 내림차순, 거래 ID 오름차순을 유지하여 생성 시각이 같아도 페이지 사이 중복·누락을 방지한다. 이전·다음 버튼과 표시 범위·전체 상세 건수·현재 페이지를 표시한다. 이동 후에는 상세 목록의 시작으로 스크롤한다.

조회 조건을 적용하거나 새 거래를 추가하면 첫 페이지로 이동하고 수정·새로고침은 현재 페이지를 유지한다. 거래 삭제·날짜 변경 등으로 현재 페이지가 사라지면 남은 마지막 페이지로 맞추며, 상세 내역이 없으면 첫 페이지와 빈 목록을 반환한다. 거래 편집·삭제 확인 중에는 페이지 버튼을 비활성화한다. 실패한 조회와 이전 요청의 응답은 최신 화면에 덮어쓰지 않는다.

페이지 응답의 합계와 보스·사냥·직접 수익 요약은 항상 조회 기간·캐릭터 전체 기준이다. 백엔드는 집계용 필드만 순회하고 마지막 조회 조건의 작은 집계 결과 하나만 보관한다. 같은 연결의 total_changes와 다른 연결 변경을 감지하는 data_version이 달라지거나 필터가 바뀌면 다시 집계한다. 상세 거래·메모·캐릭터 이름은 매번 최대 50건만 읽는다. DB 스키마 변경은 없으며 CSV와 백업에는 기존 전체 거래가 포함된다.

자동 테스트는 페이지 간 정렬·누락·중복, 기간·캐릭터별 전체 합계, 기존 사냥 지출, 범위 밖 페이지, 입력 검증, 마지막 행 삭제, 정수 범위 초과와 다른 SQLite 연결의 변경 감지를 확인한다. Electron 임시 장부에서는 101건의 직접 거래와 사냥 수입으로 페이지 이동, 합계 유지, 거래 수정·삭제·추가, 필터 변경과 빈 목록을 확인했다. 실제 사용자 장부와 API는 사용하지 않았다.
