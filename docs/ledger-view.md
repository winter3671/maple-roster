# 거래 내역의 수익 묶음과 지출

기간·캐릭터 조회 조건에 맞는 수입은 **보스 수익**과 **사냥 수익** 두 묶음으로 표시한다. 여러 날짜·캐릭터를 조회하면 해당 조건 전체를 합산하며 캐릭터 필터로 한 캐릭터의 합계를 확인할 수 있다.

- 보스 수익: 결정석 수입과 보스에서 획득한 드랍의 실제 판매 수익
- 사냥 수익: 직접 획득 메소와 사냥에서 획득한 드랍의 실제 판매 수익

각 묶음에는 금액과 원본 수입 건수를 표시한다. 수입이 없는 묶음도 0으로 표시하며 지출은 수익에서 차감하지 않는다. 상단 순수익 요약에서 전체 수입과 지출의 차이를 확인한다. 지출 내역은 날짜·캐릭터·분류·금액을 개별 행으로 표시하고 날짜 순서를 유지한다. 기존 사냥 비용과 지출 거래를 보존한다.

드랍 수익은 판매 기록의 획득 묶음을 조회하여 보스·사냥을 구분한다. 결정석은 장부 반영일, 사냥 메소와 비용은 사냥 날짜, 드랍은 실제 판매일로 필터링한다. 미판매 예상 금액은 포함하지 않는다. 판매 수정·취소나 반영일 수정 후 새로고침하면 합계에 반영한다.

표시만 묶으며 DB의 거래를 병합하거나 삭제하지 않는다. 보스·사냥 수입의 수정·취소는 원본 장부에서 진행한다. 직접 지출은 거래 내역에서 수정·삭제한다. JSON 백업은 기존 개별 거래를 유지하고 CSV 내보내기도 조회 조건에 맞는 수입·지출 원본 거래 전체를 저장한다. 대시보드는 직접 지출 분류를 추가하고 순수익·캐릭터별·날짜별 집계에 반영한다.

테스트에서는 결정석·보스 드랍·사냥 드랍의 분류, 합계와 전체 수입의 일치, 지출 제외, 판매일 필터와 판매 취소 후 합계를 확인한다. Electron 임시 장부에서 결정석 12개와 보스 드랍을 보스 수익 하나로, 사냥 메소와 드랍을 사냥 수익 하나로 표시하고 지출은 개별 행으로 유지하는 동작을 확인했다.

## 직접 지출

**지출 추가**에서 날짜·캐릭터·분류·금액·메모를 입력한다. 분류는 장비 구매·강화·큐브·아이템 구매·기타이며 API로 가져오는 기록이 아니다. 금액은 1 메소 이상 안전한 정수 범위까지, 날짜는 오늘(KST)까지, 메모는 500자까지 받는다. 금액 입력 아래에는 억·만 단위 안내를 표시한다.

지출 목록의 **수정**으로 모든 입력값을 변경한다. **삭제**는 날짜·캐릭터·금액을 확인한 뒤 적용한다. 숨긴 캐릭터의 기존 지출은 수정할 수 있으나 새 지출을 추가하거나 다른 기록을 옮길 수 없다. 같은 캐릭터의 서버가 변경되어도 과거 지출의 기록 서버는 유지한다. 다른 캐릭터로 옮기면 해당 캐릭터의 현재 서버를 기록한다. 지출이 연결된 캐릭터는 삭제 대신 숨김을 사용한다.

저장은 지출 원본과 거래를 하나의 트랜잭션으로 처리한다. 같은 저장 요청의 재시도는 한 번만 기록하고, 수정은 거래 ID를 유지하며 삭제는 대응 거래도 제거한다. 현재 조회 조건 밖에 저장한 경우 안내하고 조회 기간·캐릭터를 바꾸어 확인한다. 기존 사냥 비용은 유지하며 사냥 장부에서 관리한다.

직접 지출은 두 수익 묶음에 포함하지 않고 상단 지출·순수익 및 대시보드에 반영한다. CSV는 분류·메모·원본 ID를 포함하며 메모의 수식 주입을 방지한다. 수동·자동 JSON 백업 모두 직접 지출을 포함한다. 이전 DB 7·8·9 백업도 빈 직접 지출 목록으로 변환해 복원한다.
