# API 보스 클리어 조회와 반영

## 사용 흐름

1. 캐릭터 관리에서 API 캐릭터를 연결한다. 이전에 등록한 미연결 캐릭터도 API 목록에서 다시 체크해 같은 ID에 연결할 수 있다.
2. 보스 장부에서 **새로고침** 또는 **API 클리어 일괄 확인**을 누른다. 별도의 미리보기 없이 등록된 API 연결 캐릭터들의 완료 보스와 결정석 수익을 함께 저장한다. 빈 주차도 가능하며 프리셋 생성이 필수는 아니다.
3. 결과에서 확인·새 클리어·실패·미처리·API 미연결 개수를 확인한다. 새 보스는 1인 기준으로 등록하며 다인 파티였다면 보스명·난이도·인원을 눌러 수정한다. 수정 시 결정석 수익도 다시 계산된다.

## 일괄 자동 반영과 목요일 주차

- 로컬에 등록된 캐릭터만 조회한다. 화면의 캐릭터 필터와 관계없이 숨긴 캐릭터를 포함한 전체 API 연결 캐릭터를 순서대로 확인한다. API 미연결 캐릭터는 조회하지 않고 수동 기록을 유지한다. 계정의 다른 캐릭터를 자동으로 불러오지 않는다.
- 매주 목요일 00시(KST)~다음 수요일을 한 주차로 저장한다. 이번 주 화면을 열어 둔 상태에서 목요일이 지나 새로고침하면 새 주차로 이동한다. 지난주 클리어·수익은 그대로 보존한다. 과거 주차를 선택하면 그 주차를 확인한다.
- 새 주차에는 이전 주차의 완료 체크를 복사하지 않는다. API에서 완료를 확인한 보스만 새 주차에 추가하고 클리어·결정석 수익을 저장한다. 완료 보스가 없으면 빈 주차를 유지한다.
- 새로 추가하는 보스의 인원은 프리셋과 관계없이 1명이다. 기존 주차 기록의 인원과 가격 스냅샷은 유지한다. 미클리어 보스의 난이도를 바꿀 때에는 해당 난이도의 최대 인원으로 제한하고 주차 가격표를 적용한다.
- 이미 완료한 보스의 수익 금액·날짜·거래 ID를 유지한다. 반복 새로고침은 수익을 중복 생성하지 않는다. API 미완료·정보 없음으로 수동 클리어를 해제하거나 수익을 취소하지 않는다.
- 아직 완료하지 않은 예정 보스는 공간이 있으면 유지한다. API 완료 보스를 추가해 12개를 넘게 되면 완료 목록 밖의 메모·클리어·수익·드랍이 없는 미클리어 보스만 필요한 만큼 제외하고 결과에 개수를 표시한다. 예를 들어 루시드가 빠진 12개 구성에서 실제 완료한 12개에는 루시드가 있으면 빈 미클리어 자리를 루시드로 바꾼다.
- 기존 클리어·메모·드랍을 보존하면 12개를 초과하거나, 수익·드랍이 있는 보스의 난이도가 API와 다르면 해당 캐릭터 반영을 막고 사유를 안내한다. 미지원 보스·난이도, 가격표 누락, 중복 또는 12개 초과 완료도 반영하지 않는다.
- 저장은 캐릭터별 트랜잭션이다. 실패한 캐릭터의 변경을 모두 되돌리고 다른 캐릭터는 계속 확인한다. 키 오류·호출 제한·네트워크 오류는 이후 요청을 중단하고 미처리로 표시한다. 재시도해도 성공한 캐릭터의 수익은 중복되지 않는다.
- 조회 중 API 연결이나 해당 주차 기록이 바뀌면 덮어쓰지 않는다. 확인 도중 목요일 00시를 넘긴 경우 새 주차에서 다시 확인하도록 안내한다. 중복 일괄 요청도 차단한다.
- 공용 프리셋과 캐릭터별 기본 구성은 유지한다. 버튼을 누를 때만 조회하며 백그라운드 정기 조회는 하지 않는다. 조회 범위 밖의 주차에서는 새로고침이 저장된 기록만 다시 읽는다.

## 개별 확인과 수동 기록

자동 일괄 확인으로 새로 추가된 보스와 난이도 변경으로 인원을 추정한 보스에는 **인원 확인 필요**를 표시한다. API에는 클리어 인원이 없으므로 새 보스는 1인 기준으로 수익을 바로 반영한다. 기존에 사용자가 설정한 같은 난이도의 인원은 유지한다.

보스명·난이도·인원을 눌러 수정 창에서 **클리어 인원을 확인했습니다**를 체크하고 저장하면 1인 기록도 확인 처리할 수 있다. 보스·난이도·인원을 변경해 저장해도 표시가 해제되고 결정석 수익을 다시 계산한다. 메모나 수익 반영일만 수정하면 확인 필요 상태를 유지한다. 재조회·앱 재시작·JSON 백업 복원 후에도 상태를 유지한다.

기존 버전의 기록은 자동 등록 여부를 구분할 수 없어 소급해서 미확인으로 표시하지 않는다. 개별 API 완료 목록 교체에서 사용자가 인원을 확인해 반영한 새 기록에도 미확인 표시를 붙이지 않는다.

보스 추가·수정·삭제와 클리어 체크는 계속 사용할 수 있다. 수동으로 API 완료 보스의 체크를 해제해도 다음 일괄 확인에서 API가 완료를 응답하면 다시 클리어와 수익을 반영한다.

캐릭터 제목 옆 **API 클리어 조회**는 기존 미리보기 방식도 제공한다. 미연결·빈 주차·조회 범위 밖이면 비활성화한다. 확인 화면에서 기존 완료, API 미완료, 정보 없음, 완료 난이도 불일치를 구분하고 원하는 보스를 선택한다. 수익 반영일을 확인하고 **선택한 N개 클리어 반영**을 누르면 저장하며 조회만 하거나 확인 화면을 닫으면 장부를 변경하지 않는다.

## API 완료 목록으로 주차 맞추기

확인 화면에서 **API 완료 목록으로 주차 맞추기**를 선택하면 해당 주차를 API에서 완료한 주간 보스 목록으로 교체할 수 있다. 예를 들어 기존 구성 12개에는 루시드가 없고 실제 완료한 12개에는 루시드가 있으면, 일치하는 11개를 유지하고 구성 밖의 미클리어 보스를 제외한 뒤 루시드를 추가한다.

- 적용 전 완료 목록, 제외할 보스와 새 수익을 확인하고 **API 완료 목록으로 교체 및 반영**을 누른다. 완료한 목록이 12개보다 적으면 그 개수로 맞춘다. 아직 잡지 않은 예정 보스를 유지하려면 기존 선택 반영 방식을 사용한다.
- 일치하는 기존 기록의 ID와 메모를 유지한다. 이미 클리어한 보스의 인원·수익 금액·반영일·거래 ID도 유지한다.
- 새 보스는 같은 보스의 기존 주차 설정, 캐릭터별 구성, 1명 순으로 인원을 제안하며 해당 난이도의 최대 인원으로 제한한다. API에는 인원이 없으므로 반영 전에 확인·수정한다. 결정석 가격은 해당 주차 가격표로 계산한다.
- 같은 보스의 난이도가 다르면 미클리어 기록의 난이도를 변경하고 메모를 유지한다. 제외하는 미클리어 기록과 메모는 해당 주차에서 삭제한다.
- 제외하거나 난이도를 바꿀 기록에 기존 클리어·결정석 수익·드랍 기록이 있으면 교체를 막고 사유를 안내한다. 사용자가 기존 기록을 정리한 뒤 다시 조회해야 한다. 기존 구성에 클리어만 반영하는 기능은 계속 사용할 수 있다.
- API 완료 목록이 비어 있거나 12개 초과, 같은 보스의 여러 완료 난이도, 미지원 보스·난이도, 가격표 누락이면 교체를 막는다.
- 변경은 조회한 캐릭터의 해당 주차에만 적용하며 공용 프리셋과 캐릭터별 기본 구성은 유지한다.
- 조회 이후 주차 기록 추가·삭제·수정이나 API 연결 변경이 있으면 다시 조회해야 한다. 제거·추가·클리어·수익 저장은 하나의 트랜잭션으로 처리하여 실패 시 전체 변경을 되돌린다.

## 범위와 날짜

[공식 스케줄러 명세](references/nexon-scheduler.yaml)는 본인 계정의 캐릭터만 지원하고 요청일 기준 최대 14일 전까지 조회할 수 있다. 해당 날짜에 접속하지 않은 캐릭터는 응답이 없을 수 있다. 현재 주차는 오늘의 실시간 상태를 날짜 매개변수 없이 조회한다. 과거 주차는 마지막 수요일을 조회하며 그 날짜가 14일 범위에 있어야 한다. 미래 주차는 조회하지 않는다.

API에는 처치 시각·클리어 인원이 없으므로 정확한 수익 날짜를 추정하지 않는다. 일괄 자동 반영의 수익일은 현재 주차는 확인한 날, 과거 주차는 주차 시작일이다. 기존 수익일은 유지하며 기록 수정이나 개별 미리보기에서 주차 시작일~오늘 사이로 조정할 수 있다. 새 자동 등록 보스는 1인 기준이며 기존 기록의 인원과 가격은 보존한다. API 수익 조회나 게임 내 결정석 판매 확인 기능은 아니다.

## 매칭과 보존

- `bossWeekly` 주기만 사용한다. 일간·월간 콘텐츠는 제외한다.
- 보스 이름은 Unicode NFC·공백 정리, 난이도는 영문 easy/normal/hard/chaos/extreme을 한국어로 바꾸어 비교한다. 이름과 난이도가 함께 일치해야 반영 가능하다.
- API 미완료·정보 없음은 기존 클리어를 해제하지 않는다. 기존 수익 금액·날짜·거래 ID도 유지한다.
- 기본 선택 반영에서는 구성 밖의 완료 보스와 난이도 불일치를 표시하고 기존 구성은 유지한다. 사용자가 완료 목록 교체 방식을 선택·확인하면 누락 보스 추가와 미클리어 난이도 변경도 함께 반영한다.
- API 원문 전체를 DB나 로그에 저장하지 않는다. 필요한 보스 상태만 읽고 미리보기는 main 메모리에 최대 50개, 5분 동안 유지한다. 앱 재시작 시 다시 조회해야 한다.
- 개별 IPC 반영 요청은 서버가 발급한 미리보기 ID와 그 안의 반영 가능 기록만 허용한다. 교체 요청도 서버가 확인한 완료 목록 전체와 검증된 인원만 받으며 클라이언트가 임의로 완료 여부나 수익 금액을 지정할 수 없다. 일괄 확인 요청은 날짜만 받고 백엔드가 등록 캐릭터와 API 완료 목록을 직접 조회·검증한다.
- 반영 전에 API 연결과 보스·난이도·인원·가격·주차가 유지되는지 확인한다. 삭제·구성 변경·연결 해제·만료 시 다시 조회하도록 안내한다.
- 조회 이후 수동으로 체크한 기록은 중복 수익을 만들지 않는다. 여러 보스의 클리어·수익 반영은 한 트랜잭션이며 저장 오류 시 전체 변경을 되돌린다.

## 응답 검증과 구현

2026-10-08 실제 본인 계정 조회에서 `date`는 KST datetime, `cycle`은 `bossDaily`/`bossWeekly`/`bossMonthly`, 난이도는 영문, `complete_flag`는 문자열 true/false임을 확인했다. 명세와 실제 응답의 차이를 고려해 date 또는 KST datetime을 받되 요청 날짜와 정확히 일치해야 한다. 문자열 완료값만 허용하며, 중복 보스·난이도나 완료 필드 간 충돌은 응답 오류로 처리한다. `clear_flag` 대체 필드도 지원하되 이번 실제 조회에서 확인한 필드는 `complete_flag`다.

클라이언트는 기존 키 헤더·요청 큐·300ms 간격·제한 시간·오류 변환을 공유한다. 프로필과 스케줄러 요청도 같은 큐를 사용한다. 버튼 조회 방식으로 제공하며 주기적인 클리어 반영은 하지 않는다.

- 계약: `shared/contracts/boss-sync.contract.ts`
- API 경계: `backend/integrations/nexon/nexon.client.ts`
- 미리보기와 반영 권한: `backend/modules/bosses/boss-sync.service.ts`
- 원자적 수익 반영: `backend/modules/bosses/boss.service.ts`
- 화면: `BossRunGroups.tsx`, `BossClearPreview.tsx`, `BossesPage.tsx`

DB 마이그레이션 없이 기존 보스·결정석·장부 테이블을 사용한다. 테스트는 조회 시 무변경, 선택 검증, 수동 수익 보존, 구성 변경·장부 실패 롤백, 조회 범위·날짜·응답 검증, 만료·연결 해제를 확인한다. Electron 임시 DB에서 선택 반영·난이도 불일치·수동 완료 보존·API 실패를 가짜 응답으로 검증했고, 실제 API로도 미리보기까지 확인했다. 실제 장부에는 API 테스트 결과를 반영하지 않았고 키·OCID·캐릭터명·원문 응답을 테스트 로그에 출력하지 않았다.

완료 목록 교체는 루시드가 빠진 12개 구성의 교체, 기존 11개 기록·수동 수익 보존, 인원 변경, 난이도 변경, 보호된 기록, 조회 이후 구성 변경, 잘못된 목록·인원과 저장 실패 롤백을 추가 검증했다. Electron 임시 DB와 가짜 API에서도 화면을 통해 루시드 2인 설정과 12개 교체 결과를 확인했다.

일괄 반영은 빈 주차·숨긴 등록 캐릭터, 1인 자동 등록, 수정 인원·수동 수익 보존, 중복 수익 방지, 12개 구성 교체, 목요일 00시 전후 주차와 조회 도중 전환, 과거 수익일, 오류 시 부분 성공·호출 제한 중단, 동시 요청·기록 변경·연결 해제, 저장 롤백·미지원·중복·수동 메모 보존 한도를 테스트했다. Electron 임시 DB와 가짜 API로 새로고침과 일괄 확인 버튼, 캐릭터 필터와 무관한 전체 조회, 파티 인원 수정 유지, API 실패와 수동 장부 보존도 확인했다.
