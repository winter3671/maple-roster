# API 보스 클리어 조회와 반영

## 사용 흐름

1. 캐릭터 관리에서 API 캐릭터를 연결한다. 이전에 등록한 미연결 캐릭터도 API 목록에서 다시 체크해 같은 ID에 연결할 수 있다.
2. 보스 장부에서 프리셋으로 주차를 생성하거나 보스를 직접 추가한다.
3. 캐릭터 제목 옆 **API 클리어 조회**를 누른다. 미연결·빈 주차·조회 범위 밖은 버튼을 비활성화한다.
4. 확인 화면에서 보스와 난이도가 일치하는 API 완료 기록을 확인하고 원하는 보스만 선택한다. 기존 완료, API 미완료, 정보 없음, 완료 난이도 불일치를 구분한다.
5. 수익 반영일을 확인하고 **선택한 N개 클리어 반영**을 누른다. 클리어 체크와 결정석 수익을 함께 저장한다. 조회만 하거나 확인 화면을 닫으면 장부를 변경하지 않는다.

## API 완료 목록으로 주차 맞추기

확인 화면에서 **API 완료 목록으로 주차 맞추기**를 선택하면 해당 주차를 API에서 완료한 주간 보스 목록으로 교체할 수 있다. 예를 들어 기존 구성 12개에는 루시드가 없고 실제 완료한 12개에는 루시드가 있으면, 일치하는 11개를 유지하고 구성 밖의 미클리어 보스를 제외한 뒤 루시드를 추가한다.

- 적용 전 완료 목록, 제외할 보스와 새 수익을 확인하고 **API 완료 목록으로 교체 및 반영**을 누른다. 완료한 목록이 12개보다 적으면 그 개수로 맞춘다. 아직 잡지 않은 예정 보스를 유지하려면 기존 선택 반영 방식을 사용한다.
- 일치하는 기존 기록의 ID와 메모를 유지한다. 이미 클리어한 보스의 인원·수익 금액·반영일·거래 ID도 유지한다.
- 새 보스는 같은 보스의 기존 주차 설정, 캐릭터별 구성, 1명 순으로 인원을 제안하며 해당 난이도의 최대 인원으로 제한한다. API에는 인원이 없으므로 반영 전에 확인·수정한다. 결정석 가격은 해당 주차 가격표로 계산한다.
- 같은 보스의 난이도가 다르면 미클리어 기록의 난이도를 변경하고 메모를 유지한다. 제외하는 미클리어 기록과 메모는 해당 주차에서 삭제한다.
- 제외하거나 난이도를 바꿀 기록에 기존 클리어·결정석 수익·드랍 기록이 있으면 교체를 막고 사유를 안내한다. 사용자가 기존 기록을 정리한 뒤 다시 조회해야 한다. 기존 구성에 클리어만 반영하는 기능은 계속 사용할 수 있다.
- API 완료 목록이 비어 있거나 12개 초과, 같은 보스의 여러 완료 난이도, 미지원 보스·난이도, 가격표 누락이면 교체를 막는다.
- 변경은 조회한 캐릭터의 해당 주차에만 적용하며 공용 프리셋과 캐릭터별 기본 구성은 유지한다.
- 조회 이후 주차 기록 추가·삭제·수정이나 API 연결 변경이 있으면 다시 조회해야 한다. 제거·추가·클리어·수익 저장은 하나의 트랜잭션으로 처리하여 실패 시 전체 변경을 되돌린다.

## 범위와 날짜

[공식 스케줄러 명세](references/nexon-scheduler.yaml)는 본인 계정의 캐릭터만 지원하고 요청일 기준 최대 14일 전까지 조회할 수 있다. 해당 날짜에 접속하지 않은 캐릭터는 응답이 없을 수 있다. 현재 주차는 오늘의 실시간 상태를 날짜 매개변수 없이 조회한다. 과거 주차는 마지막 수요일을 조회하며 그 날짜가 14일 범위에 있어야 한다. 미래 주차는 조회하지 않는다.

API에는 처치 시각·클리어 인원이 없으므로 정확한 수익 날짜를 추정하지 않는다. 현재 주차는 오늘, 과거 주차는 주차 시작일을 수익 반영일 기본값으로 제공하고 사용자가 주차 시작일~오늘 사이에서 조정한다. 인원과 결정석 가격은 해당 주차 장부의 설정을 사용한다. API 수익 조회나 게임 내 결정석 판매 확인 기능은 아니다.

## 매칭과 보존

- `bossWeekly` 주기만 사용한다. 일간·월간 콘텐츠는 제외한다.
- 보스 이름은 Unicode NFC·공백 정리, 난이도는 영문 easy/normal/hard/chaos/extreme을 한국어로 바꾸어 비교한다. 이름과 난이도가 함께 일치해야 반영 가능하다.
- API 미완료·정보 없음은 기존 클리어를 해제하지 않는다. 기존 수익 금액·날짜·거래 ID도 유지한다.
- 기본 선택 반영에서는 구성 밖의 완료 보스와 난이도 불일치를 표시하고 기존 구성은 유지한다. 사용자가 완료 목록 교체 방식을 선택·확인하면 누락 보스 추가와 미클리어 난이도 변경도 함께 반영한다.
- API 원문 전체를 DB나 로그에 저장하지 않는다. 필요한 보스 상태만 읽고 미리보기는 main 메모리에 최대 50개, 5분 동안 유지한다. 앱 재시작 시 다시 조회해야 한다.
- IPC 반영 요청은 서버가 발급한 미리보기 ID와 그 안의 반영 가능 기록만 허용한다. 교체 요청도 서버가 확인한 완료 목록 전체와 검증된 인원만 받으며 클라이언트가 임의로 완료 여부나 수익 금액을 지정할 수 없다.
- 반영 전에 API 연결과 보스·난이도·인원·가격·주차가 유지되는지 확인한다. 삭제·구성 변경·연결 해제·만료 시 다시 조회하도록 안내한다.
- 조회 이후 수동으로 체크한 기록은 중복 수익을 만들지 않는다. 여러 보스의 클리어·수익 반영은 한 트랜잭션이며 저장 오류 시 전체 변경을 되돌린다.

## 응답 검증과 구현

2026-10-08 실제 본인 계정 조회에서 `date`는 KST datetime, `cycle`은 `bossDaily`/`bossWeekly`/`bossMonthly`, 난이도는 영문, `complete_flag`는 문자열 true/false임을 확인했다. 명세와 실제 응답의 차이를 고려해 date 또는 KST datetime을 받되 요청 날짜와 정확히 일치해야 한다. 문자열 완료값만 허용하며, 중복 보스·난이도나 완료 필드 간 충돌은 응답 오류로 처리한다. `clear_flag` 대체 필드도 지원하되 이번 실제 조회에서 확인한 필드는 `complete_flag`다.

클라이언트는 기존 키 헤더·요청 큐·300ms 간격·제한 시간·오류 변환을 공유한다. 프로필과 스케줄러 요청도 같은 큐를 사용한다. 버튼 조회 방식으로 제공하며 주기적인 클리어 반영은 하지 않는다.

- 계약: `shared/contracts/boss-sync.contract.ts`
- API 경계: `backend/integrations/nexon/nexon.client.ts`
- 미리보기와 반영 권한: `backend/modules/bosses/boss-sync.service.ts`
- 원자적 수익 반영: `backend/modules/bosses/boss.service.ts`
- 화면: `BossRunGroups.tsx`, `BossClearPreview.tsx`, `BossesPage.tsx`

DB 마이그레이션 없이 기존 보스·결정석·장부 테이블을 사용한다. 테스트는 조회 시 무변경, 선택 검증, 수동 수익 보존, 구성 변경·장부 실패 롤백, 조회 범위·날짜·응답 검증, 만료·연결 해제를 확인한다. Electron 임시 DB에서 선택 반영·난이도 불일치·수동 완료 보존·API 실패를 가짜 응답으로 검증했고, 실제 API로도 미리보기까지 확인했다. 실제 장부에는 API 테스트 결과를 반영하지 않았고 키·OCID·캐릭터명·원문 응답을 테스트 로그에 출력하지 않았다.

완료 목록 교체는 루시드가 빠진 12개 구성의 교체, 기존 11개 기록·수동 수익 보존, 인원 변경, 난이도 변경, 보호된 기록, 조회 이후 구성 변경, 잘못된 목록·인원과 저장 실패 롤백을 추가 검증했다. Electron 임시 DB와 가짜 API에서도 화면을 통해 루시드 2인 설정과 12개 교체 결과를 확인했다.
