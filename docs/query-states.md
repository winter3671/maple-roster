# 조회 실패와 빈 기록 구분

v0.2.5부터 대시보드·거래·사냥·보스·캐릭터·주간 콘텐츠·드랍 목록의 조회 실패를 성공한 빈 목록과 구분한다.

| 상태                 | 목록 표시             | 수익·수량 표시 | 다음 동작                |
| -------------------- | --------------------- | -------------- | ------------------------ |
| 조회 중              | 로딩 안내             | —              | 조회 완료 대기           |
| 조회 성공, 기록 있음 | 실제 기록             | 조회한 값      | 기록 확인·편집           |
| 조회 성공, 기록 없음 | 빈 기록 안내          | 실제 0         | 기록 추가·조회 조건 변경 |
| 조회 실패            | 실패 사유와 다시 시도 | —              | 조회만 재시도            |

## 동작 규칙

- `QueryFailure`는 실패 사유, 기록 없음과의 차이, 재시도 버튼을 공통으로 표시한다. 거래의 묶음 수익과 사냥의 회차 수·조각 판매 수량도 조회 결과가 없으면 0으로 대체하지 않는다.
- 사냥·보스·캐릭터의 `loadError`는 저장 오류 및 일반 피드백과 별도로 관리한다. 입력 모드 변경이나 수정창 열기처럼 일반 안내를 지워도 조회 실패를 숨기지 않는다. 정상 조회가 완료되면 실패 상태를 해제한다.
- 저장은 성공했지만 목록을 다시 불러오지 못한 경우 성공 반환값을 유지해 입력을 중복 저장하도록 유도하지 않는다. 최신 상태를 알 수 없는 목록은 실패 표시로 바꾸고 조회만 다시 실행한다. 재조회 실패 때문에 입력 보호가 계속 저장 중으로 잠기지 않는다.
- 캐릭터 목록 조회에 실패해도 장부 조회 자체가 성공한 경우 장부 결과는 표시한다. 캐릭터 필터에 별도 재시도 안내를 제공하며, 목록을 확인하기 전에는 거래의 새 기록 추가 버튼을 활성화하지 않는다.
- 보스 진행 및 정산은 주간·월간 조회 실패를 각각 안내하고 개별적으로 재시도한다.
- 주간 콘텐츠의 캐릭터별 API 오류는 기존 점수나 참여 기록 없음으로 표시하지 않고 확인 불가로 표시한다. 지난주는 실제 저장된 조회 이력이 있는 캐릭터만 표시하며, 이력이 없으면 지난주 기록 없음으로 안내한다. 전체 조회 실패는 실패한 조회 방식으로 다시 시도하고, 오류가 표시된 동안 자동 캐시 확인으로 오류를 덮어쓰지 않는다.
- 드랍 관리 창에서도 목록 조회 실패 후 창을 다시 열지 않고 재시도할 수 있다. 기존 저장 버튼과 입력 보호 규칙은 유지한다.

## 검증

실제 장부와 분리된 임시 Electron 앱에서 조회 IPC에 실패를 주입해 다음 사항을 확인했다. API 키와 실제 사용자 데이터는 사용하지 않았다.

1. 대시보드 조회 실패와 성공한 빈 거래 목록이 다른 안내를 표시한다.
2. 사냥 기록 조회 실패 안내가 입력 모드 변경 후에도 유지되고, 재시도 후 정상 빈 목록으로 돌아온다.
3. 사냥 저장 성공·목록 갱신 실패 뒤 재조회해도 사냥 기록은 1건만 존재한다.
4. 드랍 관리 창 조회 실패에서 재시도 후 정상 판매 입력이 표시된다.
5. 거래 조회 실패 때 묶음 수익이 0메소·0건으로 표시되지 않는다.
6. 캐릭터 조회 실패 상태에서도 다른 메뉴로 이동하고 캐릭터 필터를 다시 조회할 수 있다.
7. 주간·월간 보스 오류를 각각 재시도하고 보스 기록 화면에서도 실패를 빈 캐릭터 목록으로 표시하지 않는다.
8. 주간 콘텐츠 조회 실패와 지난주 저장 이력 없음이 구분된다. 기존 점수가 있는 캐릭터의 API 오류도 확인 불가로 표시한다.

타입 검사·Electron 빌드와 전체 회귀 테스트를 함께 확인한다. 이 작업은 DB 구조와 기존 저장 기록을 변경하지 않는다.
