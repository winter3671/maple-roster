# 넥슨 캐릭터 조회 연동

## 이번 단계의 범위

설정에서 암호화해 저장한 키 또는 개발용 `.env` 키로 본인 계정 캐릭터 목록을 조회하고, 사용자가 체크한 캐릭터들을 한 번에 장부에 등록한다. 기본 정보 조회는 별도의 정보 버튼으로 제공하며 등록 전에 반드시 열 필요는 없다. 기존 이름·월드·메모를 덮어쓰지 않는다. OCID 연결, 프로필 영구 저장·동기화와 보스 완료 상태는 다음 단계다.

## 파일과 책임

| 파일                                         | 책임                                                              |
| -------------------------------------------- | ----------------------------------------------------------------- |
| `backend/config/nexon-key.ts`                | 프로젝트 `.env` 읽기, UTF-8 BOM 처리, 키 유무·형식 확인           |
| `backend/config/nexon-key-store.ts`          | 암호화 파일 복원·저장·삭제, 개발용 키 우선순위와 상태 관리        |
| `desktop/main/index.ts`                      | OS safeStorage 구현과 앱 데이터 경로를 백엔드에 전달              |
| `backend/integrations/nexon/nexon.client.ts` | 고정 넥슨 URL로 요청, 응답 검증, 오류 변환, 요청 순서와 간격 제어 |
| `backend/modules/nexon/nexon.service.ts`     | 키 없는 상태 정보와 조회 기능, API에서 확인한 이름·월드로 등록    |
| `desktop/main/ipc/nexon.handlers.ts`         | 지정 창의 main frame 요청만 처리                                  |
| `shared/contracts/nexon.contract.ts`         | 화면에 제공하는 DTO와 OCID 입력 검증                              |
| `frontend/features/nexon/`                   | 연결 테스트, 캐릭터 검색·선택·등록 UI                             |

## 키 취급

- 개발과 `npm start` 미리보기에서는 `app.getAppPath()` 아래 `.env`를 읽는다.
- 환경 파일의 다른 변수는 전역 환경에 적용하지 않는다. 키를 읽지 못해도 수동 장부는 실행한다.
- `.env`는 평문 로컬 개발 파일이며 `.gitignore`로 제외한다. 키를 바꾸면 앱과 개발 서버를 재시작한다.
- 설정의 비밀번호 입력칸에서 키를 main 프로세스로 전달하고 즉시 입력을 비운다. 저장된 키는 다시 renderer로 반환하지 않는다. IPC 상태 응답은 `configured`, `issue`, `keySource`, `hasSavedKey`, `encryptionAvailable`만 반환한다.
- 인증은 공식 `x-nxopen-api-key` 헤더를 사용한다. URL·장부 DB·로그·빌드에 키를 넣지 않는다.
- API 실패 시 원본 응답 메시지와 네트워크 예외 상세를 반환하거나 기록하지 않는다.
- 패키징한 앱은 개발용 `.env`를 읽지 않으며 설정에서 키를 저장한다.

설정의 **API 키 저장**은 유효한 ASCII 키 형식만 허용하고, 실제 API 인증 확인은 별도의 **API 연결 테스트**로 수행한다. 저장된 키가 `.env`보다 우선하며 삭제하면 실행 시 읽은 개발용 키로 돌아간다. 저장·교체·삭제는 다음 요청부터 즉시 적용하고 장부 데이터를 변경하지 않는다. 이미 시작한 요청은 이전 키를 사용할 수 있다.

암호문은 `userData/secrets/nexon-api-key.bin`에 저장한다. main에서 ready 이후 OS 암호화 사용 여부를 확인하며 Linux의 `basic_text` 백엔드도 거부한다. 암호화·파일 쓰기가 실패하면 평문으로 저장하지 않고 이전 키를 유지한다. 임시 암호문 파일을 쓴 뒤 rename으로 교체한다. 파일 손상·다른 사용자 계정 등의 복호화 실패는 키 설정 오류로 표시하며 개발용 키로 조용히 대체하지 않는다. 키를 다시 저장하거나 삭제해 복구할 수 있다. 저장·복호화 오류의 원문과 키 값은 로그·IPC로 노출하지 않는다.

Windows safeStorage는 DPAPI를 사용하며 같은 사용자로 실행되는 다른 프로그램에 대한 완전한 격리를 보장하지 않는다. [Electron 공식 문서](https://www.electronjs.org/docs/latest/api/safe-storage)를 따른다. 키 파일은 장부 백업 대상에서 제외하는 것을 원칙으로 한다.

## 요청과 저장

`GET https://open.api.nexon.com/maplestory/v1/character/list`의 계정별 목록을 펼쳐 OCID로 중복을 제거하고 레벨순으로 표시한다. 계정 식별자는 화면에 전달하지 않는다. 캐릭터 선택과 등록에는 `GET /maplestory/v1/character/basic?ocid=...`을 사용하며, 날짜를 생략해 API가 제공하는 최신 정보를 조회한다.

등록 시에는 renderer가 보낸 이름·월드를 사용하지 않고 OCID로 서버에서 기본 정보를 다시 확인한다. 같은 이름·월드가 있으면 기존 캐릭터를 반환하고, 없으면 현재 수동 등록 서비스로 추가한다. 기존 캐릭터의 ID·메모·숨김 상태·장부 기록을 변경하지 않는다.

일괄 등록은 `nexon.registerMany(ocids)` IPC로 요청한다. 1~500개 선택을 검증하고 OCID 중복을 제거한 뒤 백엔드에서 순서대로 기존 등록 서비스를 호출한다. 전체 입력이 유효하지 않으면 하나도 등록하지 않는다. 각 결과는 `created`, `existing`, `failed`, `notAttempted`로 반환하며, 이미 성공한 캐릭터는 뒤의 실패 때문에 되돌리지 않는다. 키·권한·호출 한도·네트워크 오류는 남은 요청을 중단하고 미처리로 표시한다. 개별 프로필 형식 오류 등은 해당 캐릭터의 실패로 기록한 뒤 다음 캐릭터를 처리한다. 예상하지 못한 저장 오류는 내부 상세 없이 공통 메시지로 반환한다.

프론트엔드는 OCID로 체크 상태를 관리해 검색 변경에도 선택을 유지한다. 검색 결과 전체 선택은 현재 검색 결과의 미등록 캐릭터만 기존 선택에 추가한다. 이미 등록된 캐릭터는 체크를 비활성화하고 숨김 상태도 표시한다. 처리 중에는 조회·선택·등록 버튼을 잠그며, 완료 후 로컬 목록을 다시 불러온다. 성공·기등록 결과는 선택에서 지우고 실패·미처리만 남겨 재시도할 수 있다. 백엔드는 화면 이동 여부와 관계없이 이미 접수한 일괄 요청을 처리한다.

목록과 레벨·직업·길드 정보는 메모리에만 유지한다. 자동 동기화가 없으므로 이름·월드 변경은 현재 캐릭터 관리의 수동 수정으로 처리한다. 추후 OCID로 연동할 때에는 기존 ID를 유지하고, 공식 문서의 30일 이내 API 데이터 갱신 의무를 만족하는 정책을 설계해야 한다.

요청은 클라이언트 단위로 순서대로 실행하고 시작 간격을 300ms 이상 둔다. 요청당 제한 시간은 10초이며 자동 재시도는 하지 않는다. 429 응답 후에는 다음 요청을 최소 5초 늦춘다. 이 간격이 일일 호출량 한도를 보장하는 것은 아니며, 한도 오류는 UI에서 별도로 안내한다. 모든 URL은 고정된 공식 HTTPS 호스트를 사용하고 리다이렉트는 허용하지 않는다.

## 검증과 출처

키 저장소 테스트는 가짜 키와 테스트 암호화기를 사용해 암호문 파일·재실행 복원·저장 실패 시 보존·삭제·개발용 키 우선순위·손상 파일·입력 검증·키 변경 후 다음 요청 헤더를 확인한다. 실제 Electron 임시 데이터 폴더에서는 Windows safeStorage 저장·교체·재실행 복원·삭제, 비밀번호 입력칸과 저장 후 비우기, 상태 응답의 키 제외, 기존 캐릭터 보존을 검증했다. 이 검증은 실제 키 변경이나 API 호출 없이 수행했다.

Vitest에서는 가짜 키·응답과 임시 SQLite를 사용한다. 키 누락·BOM·따옴표, 인증 헤더와 DTO, OCID 검증, API 오류와 원본 메시지 차단, 요청 순서, 중복 등록과 기존 사냥 기록 보존을 확인한다. 실제 키를 사용하는 네트워크 검증은 별도 임시 DB의 Electron 화면에서 수동으로 수행했으며 실제 키와 캐릭터 이름은 검증 로그에 남기지 않았다. 빌드 산출물에 키 문자열이 없는 것도 확인했다.

일괄 등록은 중복 선택 제거, 재요청의 기등록 반환, 전체 입력 사전 검증, 개별 실패 후 성공 유지, 공통 오류 후 미처리 반환을 테스트했다. Electron 화면에서는 검색 후 체크 유지, 전체 선택·해제, 기등록 제외, 정보 조회와 체크의 분리, 부분 실패 후 실패 항목만 재시도하는 동작을 가짜 응답으로 확인했다. 실제 키로도 별도 임시 DB에 캐릭터 두 개를 등록하고 같은 요청을 재시도해 중복이 생기지 않음을 확인했다.
