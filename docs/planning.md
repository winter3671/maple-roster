# Maple Roster 기능 설계

설계 시작일: 2026-10-07 (KST). 메이플스토리 가계부의 기능 범위와 수익 집계 원칙을 정리한다. 현재 사용법과 기능은 README 및 각 장부 문서를 기준으로 확인한다.

## 목표와 전제

여러 캐릭터의 보스·사냥 수입과 관련 지출을 적은 입력으로 기록하고, 캐릭터·월드·기간별 실제 순수익을 확인하는 Electron 데스크톱 앱을 만든다. 장부는 로컬에 저장하고 Windows 설치 앱과 앱 내 업데이트를 통해 사용한다.

참고 글에서 확인한 요구는 보스 결정석·아이템·파티 분배금 계산, 과거 주차 조회, 캐릭터별 사냥 시간·수익 기록, 주간·월간 평균과 시간당 수익이다.

## 기능 설계 범위

| 기능 | 주요 동작 |
| --- | --- |
| 캐릭터 관리 | 이름으로 프로필 등록, 월드·직업·레벨·이미지 조회, 수동 등록, 표시 순서 관리 |
| 보스 장부 | 주차 선택, API 클리어 자동 결정석 정산, 수동 클리어·인원 수정, 드랍 및 분배 기록 |
| 사냥 장부 | 날짜·캐릭터·소요 시간·획득 메소·아이템 수량·메모 입력, 같은 날짜 여러 회차 등록 |
| 판매·지출 | 드랍 아이템 판매 금액·수수료·내 몫 기록, 메소·메이플포인트 지출 입력 |

## API 연결

캐릭터 프로필은 NEXON Open API를 사용한다. 보스 완료 상태는 스케줄러 API로 보조한다. 스케줄러 공식 명세는 본인 계정 캐릭터만 조회 가능하며, 요청일 기준 최대 14일 전까지 조회 가능하다고 안내한다. 해당 날짜에 접속하지 않은 경우 응답이 없을 수 있다.

API 데이터와 사용자 장부를 분리한다. 보스 완료 여부를 갱신해도 판매 금액·파티 인원·드랍·메모 등 사용자 입력은 덮어쓰지 않는다. 같은 기간·캐릭터·보스 데이터를 반복 조회해도 중복 기록을 만들지 않는다. 응답 없음이나 API 오류는 미완료로 간주하지 않는다.

획득 메소·사냥 시간·드랍 수량·실제 판매 금액의 자동 수집은 자동 수집 범위에 포함하지 않는다. 보스 클리어 확인은 결정석 판매 확인과 다르다. API 키가 없어도 수동 장부는 사용할 수 있게 한다.

개인용은 사용자의 API 키를 로컬에서 사용하는 방식으로 시작한다. 공개 배포 시 공용 비밀 키를 앱에 포함하지 않으며, 사용자별 키 입력 또는 넥슨 인증 연동과 서버 구성을 별도로 검토한다. 실제 키를 이용한 응답·권한 검증은 구현 착수 시 실시한다.

## 수익 집계 규칙

- 실제 순수익 = 판매·수령이 확정된 수입 − 실제 지출.
- 미판매 드랍은 수량과 예상 가치만 기록한다. 판매 시 실제 수입을 한 번 생성하고 판매한 수량을 차감한다. 일부 판매를 지원한다.
- 기록 당시 단가·수수료·분배 결과를 저장하여 현재 시세나 설정 변경이 과거 장부를 바꾸지 않게 한다.
- 결정석 예상 내 몫은 가격표와 파티 인원으로 계산하되, 실제 수령액으로 수정할 수 있게 한다. 가격표는 적용일별로 관리한다.
- 드랍 판매는 전체 판매대금, 수수료, 내 분배 금액을 구분한다. 균등 분배를 기본으로 하며 내 몫 직접 입력도 허용한다.
- 보스 진행률은 클리어 주차 기준, 실제 수입은 판매·수령일 기준으로 집계한다. 정확한 클리어 일자를 API가 제공하지 않으면 임의로 생성하지 않는다.
- KST 기준 기간을 사용한다. 일간·주간·월간 리셋 규칙은 구현 시 공식 게임 자료로 확인하고 설정 데이터로 관리한다.
- 새 기간에는 새 기록을 만든다. 과거 기록을 지우는 방식으로 초기화하지 않는다.
- 월드·캐릭터 이동 및 이름 변경에도 장부 ID는 유지한다. 과거 집계용 월드는 기록 당시 값을 보존한다.
- 사냥 시간당 획득 수익은 직접 획득 메소와 회차에 귀속된 판매 수익에서 소모 비용을 뺀 값을 실제 사냥 시간으로 나눈다. 미판매 아이템을 포함한 예상 수익은 별도 지표다.
- 전체 시간당 수익은 총수익 ÷ 총시간으로 계산한다. 회차별 시간당 수익의 단순 평균을 사용하지 않는다. 시간 0인 기록은 시간당 계산에서 제외한다.
- 캐릭터 사이 메소 이동은 수입·지출이 아닌 내부 이동으로 처리하여 전체 수익을 늘리지 않는다.

## 화면과 주요 흐름

사이드바: 대시보드 / 보스 장부 / 사냥 장부 / 거래 내역 / 캐릭터·설정.

보스 장부는 여러 캐릭터를 한 화면에서 비교하는 표 형태를 기본으로 한다. 기간 선택, 캐릭터별 클리어·예상 수입·확정 수입 합계, 행 펼치기와 상세 정산을 제공한다. 보스 구성 프리셋은 다음 주차에 재사용한다.

사냥 장부는 빠른 입력 폼과 회차 목록을 함께 보여준다. 최근 사용 캐릭터·사냥터·시간·소모 비용을 재사용한다. 획득 메소, 드랍 수량, 판매 여부와 실제 수익을 구분한다. 타이머는 수동 시간 입력이 안정된 이후 선택적으로 추가한다.

흐름: 캐릭터 등록 → 보스 프리셋 작성 → 클리어 확인 → 결정석 판매 및 드랍 기록 → 판매 시 정산 → 주간·월간 결산 확인. 사냥은 회차 기록 후 같은 판매·정산 구조를 사용한다.

## 구현 구조 제안

Electron + React + TypeScript + Tailwind CSS UI, SQLite 로컬 데이터베이스를 사용한다. 프론트엔드와 백엔드의 책임을 분리하고, Electron IPC로 연결한다. 구체적인 파일 구조와 개발 흐름은 [아키텍처 기획](architecture.md)을 따른다. UI와 계산 로직을 분리하여 추후 캐릭터 성장 기록을 추가할 수 있게 한다.

- Renderer: 화면, 입력, 상태 표시.
- Preload: 허용한 기능만 노출하는 타입 지정 IPC 인터페이스.
- Main: API 요청, 키 보관, DB 읽기·쓰기, 백업·복원.
- Domain: 기간 구분, 수익 계산, 판매 수량 정산, 중복 방지 규칙.

최소 데이터 단위는 캐릭터, 보스 프리셋, 보스 기간 기록, 사냥 회차, 아이템 획득·판매, 거래 장부, 적용일별 보스 가격표, API 동기화 상태다. 장부 거래는 원본 활동에 연결하고 정정·삭제 시 함께 처리한다. 메소는 정수로 저장하고 부동소수점으로 정산하지 않는다.

API 키는 main에서 Electron safeStorage로 보호하고 백업과 로그에 포함하지 않는다. UI의 Node 접근을 끄고 contextIsolation과 sandbox를 켠다. API 캐시 갱신 정책은 넥슨의 30일 이내 갱신 고지를 반영한다.

## 개발 순서와 완료 기준

1. 실제 API 응답·권한 확인과 집계 규칙 확정. 보스 완료 상태와 금액 확정의 차이를 검증한다.
2. Electron 골격, SQLite, 캐릭터 등록, 수동 장부 및 백업·복원. API 연결 없이도 기록이 가능해야 한다.
3. 보스 프리셋·기간 조회·결정석·드랍 정산. 반복 갱신이 수입을 중복 생성하지 않아야 한다.
4. 사냥 회차·아이템 판매·시간당 수익. 일부 판매, 수수료, 회차별 비용을 검산한다.
5. 대시보드, 기간 경계 검증, Windows 패키징. 재실행·백업 복원 후 같은 합계가 나와야 한다.

첫 버전은 보스 여러 캐릭터 기록, 사냥 여러 회차 기록, 드랍 판매와 지출 기록을 합쳐 월간 실제 순수익이 맞는 상태를 완료로 본다.
