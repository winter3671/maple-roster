# JSON 장부 백업과 복원

## 사용 방법

**설정 → 백업과 복원 → JSON 백업 저장**을 누르고 저장할 위치를 선택한다. 백업에는 캐릭터와 API 연결·프로필, 숨김·메모, 공용 보스 묶음과 캐릭터별 구성, 주간 보스 기록·결정석 수익, 사냥 회차, 드랍 획득·판매와 거래 내역이 들어간다. 원래 기록의 ID·날짜·금액·인원을 그대로 보관한다.

API 키와 암호화한 키 파일, 개발용 `.env`, API 응답 캐시와 미리보기는 포함하지 않는다. 백업 파일은 평문 JSON이며 캐릭터 이름·OCID·메모와 장부 내용을 포함한다.

**백업 파일로 복원**을 누르고 앱에서 저장한 JSON 파일을 선택한다. 검증을 통과하면 생성 시각과 현재 장부·복원할 백업의 기록 수를 비교해서 보여준다. 파일 선택만으로 기록을 변경하지 않는다. 전체 교체 확인에 체크한 뒤 **장부 전체 복원**을 누르면 적용한다. 취소하면 현재 장부를 유지한다.

## 전체 교체와 안전 백업

- 첫 버전의 복원은 전체 교체다. 백업과 현재 기록을 합치지 않으며, 백업 이후 추가한 기록은 복원된 장부에 포함되지 않는다.
- 복원 직전 현재 장부를 앱 데이터 폴더의 `backups/before-restore-시각-고유ID.json`으로 자동 저장한다. 같은 이름으로 덮어쓰지 않고 이전 안전 백업도 유지한다. 성공 메시지에 안전 백업의 전체 경로를 표시한다.
- 되돌리려면 같은 복원 기능에서 해당 안전 백업 파일을 선택한다. 되돌리는 작업 역시 적용 직전의 장부를 안전 백업한다.
- 안전 백업을 저장하지 못하면 교체를 시작하지 않는다. DB 삭제·삽입은 하나의 트랜잭션이며 저장 실패 시 원래 장부로 되돌린다.
- 현재 PC의 API 키 설정과 DB 마이그레이션 이력은 교체하지 않는다. 다른 PC에서 복원하면 API 키를 따로 설정해야 한다.
- 조회 중인 API 요청이나 다른 작업이 있으면 복원을 막는다. 파일을 확인한 뒤 장부가 달라져도 다시 선택해야 한다. 복원 확인은 10분 동안 유효하고, 복원 성공 시 기존 보스 API 미리보기를 폐기한다.
- 복원 후 다른 화면으로 이동하면 복원된 장부를 불러온다. 앱을 재시작하지 않아도 사용할 수 있다.

## 형식과 검증

현재 지원 형식은 `format: "maple-roster"`, `version: 1`, `schemaVersion: 7`이다. 파일에는 UTC `createdAt`과 현재 10개 업무 테이블의 `tables`가 들어간다. 지원 DB 버전과 정확히 일치하는 백업만 받는다. 첫 백업 버전에는 이전·이후 스키마 변환 기능을 제공하지 않는다.

파일은 UTF-8 JSON이며 BOM도 읽을 수 있다. 저장·복원 한도는 50MB, 전체 테이블 합계 20만 기록이다. 저장은 같은 폴더의 임시 파일에 먼저 기록하고 디스크에 반영한 뒤 최종 파일명으로 교체한다. 복원 시 사용자 파일을 SQL로 실행하지 않으며 테이블·컬럼은 앱의 고정 목록만 허용한다.

실제 장부 대신 별도의 메모리 DB에서 먼저 검증한다.

- 형식·버전·테이블·컬럼, UUID, 날짜·UTC 시각, 정수 범위와 자료형
- DB의 필수 값·유일성·체크 제약·외래 키와 캐릭터 연결
- 목요일 주차와 캐릭터별 주간 12개 한도, 묶음 구성·중복
- 사냥 조각·젬스톤의 획득 수량과 자동 아이템 기록
- 드랍 출처·캐릭터·월드, 획득 수량을 넘지 않는 판매와 분배금
- 자동 결정석 수익 계산, 실제 수익·비용·판매와 거래 장부의 금액·날짜·참조 일치

과거 보스명·가격 스냅샷과 수동 수령액을 최신 카탈로그 값으로 다시 계산하지 않는다. 수동 수익은 백업에 저장된 값으로 보존한다.

## 구현과 확인

- `backend/modules/backup/backup.service.ts`: 일관된 JSON 내보내기, 임시 DB 검증, 확인 토큰과 전체 복원
- `backend/modules/backup/backup.files.ts`: 파일 크기·UTF-8 검사, 임시 파일 교체와 안전 백업 저장
- `desktop/main/ipc/backup.handlers.ts`: 운영체제 저장·열기 대화상자와 복원 요청
- `frontend/features/settings/BackupManager.tsx`: 비교 표·전체 교체 확인·결과 안내
- `shared/contracts/backup.contract.ts`: UI에 반환하는 요약·결과 계약

백업 테스트는 모든 기록의 왕복 보존, 빈 장부 복원과 되돌리기, 손상 데이터·참조·금액·판매 수량·누락 거래·자동 아이템 검증, 만료·취소·장부 변경과 실패 롤백을 확인한다. 파일 테스트는 저장 실패 시 원본 보존, 임시 파일 정리, UTF-8 검사와 안전 백업의 고유 이름을 확인한다. Electron 격리 테스트에서는 파일 대화상자 반환값과 API를 가짜로 제공하되 실제 파일·DB·IPC·화면으로 저장, 확인·취소, 진행 중 요청 차단, 복원 전 백업, API 키 보존과 재시작 후 유지 여부를 확인했다.
