# 보스 묶음 프리셋과 캐릭터별 구성

## 사용 흐름

1. 보스 장부의 **묶음 프리셋 만들기**에서 이름을 입력하고 보스 1~12개를 구성한다. 각 보스의 난이도·클리어 인원을 선택하면 예상 수익을 표시한다. 같은 보스의 여러 난이도를 동시에 넣을 수 없다.
2. **익세노흉 예시로 만들기**는 요청한 12개 조합을 채워준다. 인원은 모두 1명으로 시작하므로 실제 파티 인원으로 조정한 뒤 저장한다. 예시는 자동 저장하지 않는다.
3. **캐릭터에 할당**에서 여러 캐릭터를 체크하고 한 번에 적용한다. 선택한 캐릭터의 현재 구성 전체를 교체한다. 기존 개별 수정도 교체하므로 화면에 교체 범위를 안내한다.
4. **캐릭터 구성 수정**으로 그 캐릭터의 보스 교체·추가·제거, 난이도·인원을 조정한다. 다른 캐릭터와 공용 프리셋은 유지된다.
5. **프리셋으로 주차 생성**을 누르면 캐릭터별 구성으로 주차 기록을 만든다. 클리어·결정석 판매·드랍 관리는 기존 흐름을 사용한다.

공용 묶음과 캐릭터별 구성은 같은 편집 화면을 사용한다. 새 구성은 최대 12개이며 12개를 모두 채우지 않아도 저장할 수 있다. 기존 보스 목록·난이도·입장 인원 검증과 적용일별 결정석 자동 가격표를 공유한다.

## 복사와 보존 규칙

- 할당은 연결된 실시간 동기화가 아니라 구성 복사다. 캐릭터마다 현재 구성은 하나이며 여러 캐릭터에 같은 묶음을 할당할 수 있다.
- 공용 묶음 수정·이름 변경은 이미 할당한 구성에 전파되지 않는다. 새 버전을 쓰려면 다시 할당한다. 캐릭터 화면의 묶음 이름은 할당 당시 이름이다.
- 개별 구성을 저장하면 ‘개별 수정’으로 표시한다. 이 표시는 개별 저장 여부이며 원본과의 정밀한 차이 비교는 아니다.
- 공용 묶음 삭제는 할당본을 지우지 않는다. 원본 연결만 비우고 캐릭터의 보스 구성·이름을 보존한다.
- 캐릭터별 구성을 **공용 프리셋으로 저장**하여 별도 이름의 새 묶음을 만들 수 있다. 새 묶음은 현재 보스 목록에 있는 조합으로 저장한다.
- 구성 수정·재할당은 이미 생성된 주차·판매·드랍 기록을 변경하지 않는다. 반복 주차 생성은 기존 기록을 유지하고 그 주차에 없는 보스만 추가한다. 이미 기록이 있는 주차에서 보스 구성을 교체하면 행 수가 12개를 넘을 수도 있으며 기존 기록은 수동으로 정리한다.
- 숨김 캐릭터는 새 할당·구성 수정에서 제외한다. 전체 선택에서 숨김 캐릭터가 섞이면 일괄 작업을 롤백한다.
- 일괄 할당은 한 트랜잭션이다. 캐릭터 누락·숨김·저장 오류가 있으면 모든 선택 캐릭터를 이전 상태로 되돌린다.

## 저장 구조와 이전 데이터

DB 5번 마이그레이션은 `boss_templates`(이름·보스 구성 JSON)와 `boss_roster_assignments`(캐릭터별 할당 당시 이름·원본 ID·개별 저장 여부)를 추가한다. 보스 구성 자체는 기존 `boss_presets`의 캐릭터별 행을 사용한다. 기존 주차 생성·판매·드랍 저장 구조를 유지한다.

기존 캐릭터별 행은 ‘기존 보스 구성’으로 묶어 보여준다. 기존 행 ID·인원·가격·주차·판매 기록을 변경하지 않는다. 12개를 넘는 과거 구성도 자동 삭제하지 않으며 새로 저장할 때 12개 이하로 정리한다. 기존 자유 입력 이름·난이도·인원은 변경하지 않으면 유지할 수 있다.

주요 파일은 `shared/contracts/boss-roster.contract.ts`, `backend/modules/bosses/boss-roster.service.ts`, `frontend/features/bosses/BossRosterManager.tsx`, `BossRosterEditor.tsx`다. Electron의 명시적 IPC 경로로 저장하며 API 키는 필요하지 않다.

## 12개 기준과 검증

12개는 사용자가 요청한 앱의 묶음 크기다. 게임의 주간 보스 처치 한도로 단정하지 않는다. [2026-09-17 공식 업데이트](https://maplestory.nexon.com/News/Update/813)는 캐릭터당 주간 결정 판매 12개 제한을 삭제했으며 월드당 판매 수량 제한은 유지한다. 앱은 게임의 처치·판매 수량 제한을 강제하지 않는다.

통합 테스트는 다중 할당, 개별 보스 교체, 공용 수정·삭제의 독립성, 재할당 후 정산 보존, 구성 크기·중복·난이도·인원 검증, 일괄 롤백과 기존 DB 업그레이드를 확인한다. 실제 Electron에서는 예시 12개 저장, 두 캐릭터 체크 할당, 한 캐릭터 수정, 공용 수정 후 독립성, 24개 주차 생성과 재실행 보존을 임시 DB로 확인했다.
