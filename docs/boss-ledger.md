# 주간 보스 장부

## 사용 흐름

1. 캐릭터를 등록한다.
2. 보스 장부의 프리셋 관리에서 캐릭터, 주간 보스 이름, 난이도, 파티 인원(1~6명), 결정석 전체 가격을 입력한다. 전체 가격은 파티 분배 전 금액이며 모르면 0을 입력한다.
3. 원하는 주차와 캐릭터를 선택하고 **프리셋으로 주차 생성**을 누른다. 전체 캐릭터를 선택하면 표시 중인 캐릭터의 프리셋을 함께 적용한다.
4. 보스를 클리어했으면 체크한다. 이 단계는 수입을 생성하지 않는다.
5. 실제 결정석을 판매했으면 판매 기록에서 판매일과 실제 내 수령액을 저장한다. 처음에는 전체 가격 ÷ 파티 인원을 내림한 예상액을 채워주며 실제 금액으로 수정할 수 있다.
6. 거래 내역과 대시보드에서 판매일 기준 수입을 확인한다.

보스 이름은 수동 입력하며 NFC 정규화·공백 제거·소문자 변환 후 중복 검사 키를 만든다. 같은 캐릭터·같은 이름은 난이도를 달리해도 한 프리셋만 허용한다. 별칭·오타나 이름에 난이도를 포함한 경우 같은 보스로 인식하지 못하므로 일관된 이름을 입력한다. 공식 카탈로그·단가 적용일 관리와 API 보스 식별자 연결은 후속 단계다.

## 주차와 스냅샷

주간 보스 주차는 KST 목요일 0시부터 다음 수요일까지다. 날짜 입력은 그 날짜가 속한 목요일 주차로 변환한다. 조회는 2000-01-06부터 허용하며 미래 주차 생성은 막는다. 날짜를 바꿔도 기존 주차 기록은 삭제하지 않는다. 일간·월간 보스는 이번 단계에서 지원하지 않는다.

주차를 만들 때 프리셋의 보스·난이도·파티 인원·가격과 캐릭터의 당시 월드를 복사한다. `(캐릭터 ID, 보스 키, 주차)`로 중복을 막고 반복 생성은 기존 기록을 덮어쓰지 않는다. 프리셋 변경은 이후 새로 생성하는 기록에만 적용한다. 과거 주차를 처음 생성하면 현재 프리셋 값이 사용되므로 필요하면 그 주차 기록을 수정한다. 캐릭터 이름은 현재 이름을 보여주고 월드는 기록 당시 값을 유지한다.

프리셋 수정은 캐릭터·보스 이름을 바꾸지 못하고 난이도·인원·가격만 변경한다. 프리셋을 삭제해도 기존 주차와 판매 이력은 남긴다. 숨긴 캐릭터의 기존 기록은 조회·수정할 수 있지만 새 프리셋과 새 주차 생성에서는 제외한다.

## 결정석 정산

- 클리어되지 않은 기록은 판매를 확정할 수 없다.
- 판매일은 보스 주차 시작일부터 오늘까지의 실제 날짜를 입력한다. 정확한 클리어 일자는 저장하지 않으므로 클리어 당일 여부는 자동 검증하지 않는다.
- 예상 내 몫은 `floor(결정석 전체 가격 / 파티 인원)`이다. 실제 수령액은 별도 입력이며 0 이상 안전한 정수 메소다.
- 보스 기록당 정산은 하나다. 반복 저장은 기존 정산을 수정하고 거래를 중복 생성하지 않는다.
- 0 메소는 판매 상태만 기록하고 장부 거래는 만들지 않는다.
- 판매일·금액 수정은 기존 정산과 거래 ID를 유지한다. 판매 금액을 0으로 수정하면 연결 거래를 제거한다.
- 판매 취소는 정산과 연결 수입을 함께 지우고 클리어 상태를 유지한다.
- 판매가 있는 기록의 클리어 해제·주차 내용 수정·삭제는 판매 취소 후 허용한다.
- 보스 기록 삭제는 해당 주차만 삭제하며 프리셋은 남긴다. 다시 주차 생성하면 삭제한 보스가 새 미완료 기록으로 생성된다.

판매와 연결 거래는 동일 트랜잭션으로 처리한다. 장부 저장·수정·삭제가 실패하면 정산 변경도 롤백한다. 프리셋으로 여러 주차 행을 생성하는 작업도 하나의 트랜잭션으로 처리한다.

보스 화면은 선택한 클리어 주차의 진행률, 클리어 후 미판매 예상액, 해당 주차에 연결된 실제 수령액을 표시한다. 거래 내역과 대시보드는 판매일 기준으로 집계한다. 예를 들어 9월 주차의 결정석을 10월 1일에 판매하면 9월 주차의 정산과 10월 장부 수입에 각각 표시되며 이중 합산하지 않는다.

## 구현 구조

| 영역 | 주요 파일 |
| --- | --- |
| 계약·검증 | `shared/contracts/boss.contract.ts`, `shared/boss-period.ts` |
| 계산 | `backend/domain/boss-profit.ts` |
| 저장·업무 | `backend/modules/bosses/boss.repository.ts`, `boss.service.ts` |
| DB 갱신 | `backend/database/migrations/003_bosses.sql` |
| Electron 연결 | `desktop/main/ipc/boss.handlers.ts`, preload |
| 화면 | `BossesPage.tsx`, `BossPresetForm.tsx`, `BossRunForm.tsx`, `useBosses.ts` |

장부 거래에 사냥 회차 또는 결정석 정산 중 정확히 하나의 원본을 연결한다. DB 3번 마이그레이션은 기존 사냥 거래를 복사해 ID와 금액을 유지하고 보스 거래의 외래 키를 추가한다. 보스·사냥 프리셋과 기록이 있는 캐릭터는 삭제를 막고 숨김을 사용한다.

## 현재 제한과 검증

자동 보스 목록·가격표·드랍 판매·파티 드랍 분배·API 완료 조회는 후속 단계다. 주간 기록은 캐릭터 단위이며 월드·계정 공통 보상이나 실제 게임의 처치·판매 횟수 제한을 강제하지 않는다. 완료 상태는 수동이고 정확한 처치 일자는 추정해서 저장하지 않는다.

Vitest에서 목요일 KST 경계, 월·연 경계, 정수 파티 분배, 반복 주차 생성·정산 중복 방지, 프리셋·월드 스냅샷, 판매일 집계, 0 메소, 정산 수정·취소, 캐릭터 삭제 보호, 롤백과 기존 DB 업그레이드를 검증했다. Electron에서는 프리셋 생성, 주차 이동, 클리어와 수입 분리, 실제 판매·수정·취소, 거래·대시보드 반영과 재실행 후 메모 보존을 별도 임시 DB로 검증했다.
