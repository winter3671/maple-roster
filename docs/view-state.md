# 조회 조건과 화면 선택 유지

메뉴 이동 시 페이지는 계속 해제하며, 작은 조회 조건만 페이지 바깥의 `ViewStateProvider`에 기억한다. 기록 목록과 API 응답은 캐시하지 않고 다시 진입할 때 조회한다.

## 적용 범위

| 화면                | 기억하는 내용                                |
| ------------------- | -------------------------------------------- |
| 대시보드            | 조회로 적용한 시작일·종료일·캐릭터           |
| 사냥 장부           | 적용한 기간·캐릭터, 빠른 기록/상세 기록 모드 |
| 거래 내역           | 적용한 기간·캐릭터, 거래 목록 페이지         |
| 보스 장부           | 진행도/주간/월간 화면 선택                   |
| 보스 진행도 및 정산 | 주간 기준일·월간 기준월·캐릭터               |
| 주간·월간 보스 기록 | 각각 독립적인 기준 기간·캐릭터               |
| 주간 콘텐츠         | 이번 주/지난주 선택                          |

적용하지 않은 조회 입력, 수정창, 오류, API 결과, 스크롤 위치는 기억하지 않는다. 작성 중인 장부 입력은 별도의 입력 보호 기능을 사용한다.

## 수명과 보정

- 앱을 켜 둔 동안 유지한다. 재실행 시 현재 기간·기본 화면·거래 1페이지로 시작한다. 이전 달이나 주차가 재실행 후 기본값으로 고정되지 않는다.
- 조회 조건을 새로 적용하면 거래 페이지를 1로 되돌린다. 페이지를 바꿀 때 기간·캐릭터는 유지한다.
- 기록 삭제 등으로 페이지 수가 줄면 서버가 반환한 실제 페이지로 기억한 값을 보정한다. 이전 조건의 늦은 응답으로 새 조건이나 페이지를 덮어쓰지 않는다.
- 캐릭터 목록 조회에 성공한 뒤 선택한 캐릭터가 없으면 기간은 유지하면서 전체 캐릭터로 변경한다. 거래 페이지도 1로 되돌린다. 로딩·조회 실패를 캐릭터 삭제로 간주하지 않는다.
- 조회 조건과 선택값만 메모리에 유지하며 API 키나 장부 데이터는 포함하지 않는다. 저장소와 백업 형식은 변경하지 않는다.

## 검증

`view-state.test.ts`는 장부 간 조건 분리, 새 실행의 기본값, 최신 상태 업데이트, 조회 객체의 안정성, 구독 해제, 삭제된 캐릭터 판정, 오래된 페이지 응답 방어를 검증한다. 실제 Electron에서는 별도의 임시 장부를 사용해 메뉴 복귀, 보스 하위 화면 전환, 거래 페이지 유지·보정과 캐릭터 삭제 후 조건 정리를 확인한다.
