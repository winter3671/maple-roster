# Maple Roster

메이플스토리 캐릭터들의 보스·사냥 수입과 지출을 기록하는 개인용 Electron 데스크톱 앱입니다.

여러 캐릭터의 기록을 한곳에 모아 캐릭터별·기간별 실제 순수익을 확인하는 것을 목표로 합니다. NEXON Open API로 캐릭터 정보와 보스 완료 상태를 조회하고, 판매·분배 금액은 장부에 기록하는 방식으로 기획하고 있습니다.

프론트엔드와 백엔드를 분리하고, 화면 입력부터 요청 검증·업무 처리·DB 저장까지 직접 구현하며 연습하는 프로젝트입니다.

## 현재 상태

**캐릭터 관리, 보스·사냥 장부, 드랍 판매와 넥슨 캐릭터 조회를 사용할 수 있습니다.** 캐릭터를 수동 등록하거나 본인 계정의 API 목록에서 선택한 뒤 장부를 기록할 수 있으며, 앱을 다시 열어도 기록이 유지됩니다. 사냥 메소·비용, 보스 클리어 결정석 수익과 드랍 판매는 거래 내역에 반영됩니다. 대시보드는 주간·월간·직접 지정한 기간의 실제 수익 추이와 캐릭터별·수익 분류별 합계를 표시합니다. 캐릭터 프로필 저장·갱신, API 보스 클리어 일괄 자동 정산과 JSON 백업·복원을 지원하며, 개인용 Windows x64 설치 파일을 생성할 수 있습니다.

사냥 기록은 날짜, 시간(분), 직접 획득한 메소, 소모 비용, 솔 에르다 조각·코어 젬스톤 수량과 메모를 입력합니다. 아이템은 판매할 때 실제 내 몫이 수익에 포함됩니다. 시간이 0분인 기록은 시간당 계산에서 제외하며, 여러 회차의 시간당 순수익은 시간이 기록된 회차의 총 순수익 ÷ 총시간으로 계산합니다. 시간당 메소는 소수점 이하를 내림합니다.

사냥·보스 기록의 **드랍 관리**에서 획득 아이템과 예상 단가를 입력하고 일부 수량씩 판매할 수 있습니다. 전체 판매대금·실제 수수료·분배 인원을 입력하면 균등 분배한 내 몫을 계산하거나 실제 분배금을 직접 입력할 수 있습니다. 미판매 예상 금액은 실제 수입에서 제외합니다. 조각·젬스톤은 사냥 회차의 수량으로 자동 생성되며 기존 기록도 연결됩니다. 사냥 수익은 사냥 날짜에 연결된 판매 수익을 포함하지만, 거래 장부는 판매일 기준입니다. 상세 규칙은 [드랍 판매](docs/drop-sales.md)를 참고하세요.

보스 장부는 주간 보스부터 지원합니다. **보스 묶음 프리셋**에 이름을 붙이고 주간 보스 1~12개를 구성한 뒤 여러 캐릭터를 체크해 할당합니다. 캐릭터별 구성에서 보스·난이도·인원을 개별 조정한 뒤 **프리셋으로 주차 생성**을 누릅니다. 할당은 복사 방식이므로 공용 묶음이나 다른 캐릭터의 수정이 전파되지 않습니다. 주차는 목요일 0시(KST)부터 수요일까지이며 기존 기록은 재생성해도 유지됩니다. **클리어**를 체크하면 결정석 수익이 바로 장부에 반영되고 체크 해제 시 취소됩니다. 기록의 난이도·인원을 수정하면 수익도 자동 갱신됩니다. 수익 반영일은 현재 주차에서는 오늘, 과거 주차에서는 주차 시작일이며 기록 수정에서 변경할 수 있습니다. 프리셋 수정은 새로 생성하는 기록에만 반영되고 과거 기록을 바꾸지 않습니다.

보스 화면의 결정석 수익은 해당 주차의 클리어 수익 합계입니다. 거래 내역과 대시보드는 수익 반영일 기준으로 집계합니다. 기존 직접 입력 수령액·날짜는 보존하고, 클리어만 체크했던 기록은 자동 수익으로 전환합니다. 공식 가이드 기준 주간 보스 24종의 [보스·난이도 목록](docs/boss-catalog.md)을 제공합니다. 보스·난이도별 최대 인원만 선택할 수 있고 결정석 가격과 예상 내 몫은 자동 계산됩니다. 가격표는 2026-10-08 확인 기준이며 지원 가격 이력은 2026-06-18부터입니다(벨로나는 8월 20일부터). 기존에 직접 입력한 보스·난이도는 유지됩니다. 일간·월간·계정 공통 보상 및 게임 내 처치·판매 횟수 제한은 이번 단계에서 자동 검증하지 않습니다.

보스 목록은 서버와 캐릭터별로 묶어 표시합니다. 보스명·난이도·인원을 누르면 수정 화면이 열리고, 캐릭터별 **+ 보스 추가**와 빨간 **×**로 해당 주차의 구성을 조정할 수 있습니다. 결정석 내 몫에는 금액만 표시합니다. 같은 주차의 중복 보스와 12개 초과 등록은 막으며, 주차 기록 수정은 프리셋에 반영되지 않습니다.

**API 클리어 조회 → API 완료 목록으로 주차 맞추기**로 실제 완료한 보스들에 맞춰 해당 주차 구성을 교체할 수 있습니다. 누락 보스는 추가하고 완료 목록 밖의 미클리어 기록은 제외하며, 기존에 일치하는 클리어 수익은 유지합니다. 새 보스의 인원은 반영 전에 확인합니다. 제외·난이도 변경 대상에 클리어 수익이나 드랍이 연결되어 있으면 보호를 위해 교체를 막고 사유를 안내합니다. 프리셋은 변경하지 않습니다.

**새로고침** 또는 **API 클리어 일괄 확인**을 누르면 등록된 전체 API 연결 캐릭터의 완료 보스를 자동 등록하고 클리어·결정석 수익을 함께 반영합니다. 빈 주차도 바로 확인할 수 있으며 새 보스는 **1인 기준**입니다. 다인 파티였다면 보스명·난이도·인원을 눌러 수정하세요. 기존 인원·수동 수익은 유지하고 반복 확인으로 수입을 중복 생성하지 않습니다. 목요일 00시(KST) 이후에는 새 주차에 기록하며 지난주 기록을 보존합니다. 캐릭터 필터와 관계없이 숨긴 API 연결 캐릭터도 확인하고, 실패·미처리·미연결 결과를 표시합니다. 수동 등록·클리어 체크와 개별 미리보기도 계속 사용할 수 있습니다.

## 주요 기능 계획

**설정 → 결정석 가격표 관리**에서 보스·난이도별 수동 가격을 적용일·확인일·출처와 함께 등록하고 이력을 조회·수정·삭제할 수 있습니다. 새 기록에는 해당 날짜의 가격을 사용하고 기존 보스 기록의 금액은 보존합니다. 수동 가격표도 JSON 백업에 포함합니다. 공식 가격을 자동 조회하지 않습니다.

API 일괄 확인으로 새로 등록하거나 난이도 변경으로 인원을 추정한 보스에는 **인원 확인 필요**가 표시됩니다. 수익은 바로 반영하며, 수정 창에서 인원 확인을 체크하거나 보스·난이도·인원을 변경해 저장하면 표시가 해제됩니다. 메모·날짜만 수정하면 유지됩니다. 기존 버전의 기록은 소급해서 미확인 처리하지 않습니다.

| 기능        | 내용                                                                |
| ----------- | ------------------------------------------------------------------- |
| 캐릭터 관리 | 캐릭터 등록, 프로필 조회, 표시 순서와 숨김 설정                     |
| 보스 장부   | 캐릭터별 보스 프리셋, 클리어 즉시 결정석 수익 반영과 드랍 분배 기록 |
| 사냥 장부   | 회차별 사냥 시간, 획득 메소, 드랍 수량과 소모 비용 기록             |
| 거래 내역   | 아이템 판매, 기타 수입과 구매·강화 등 지출 기록                     |
| 대시보드    | 주간·월간 순수익, 캐릭터별 합계와 수익 추이                         |
| 데이터 관리 | 로컬 자동 저장, JSON 백업·복원과 CSV 내보내기                       |

첫 버전은 개인용 로컬 앱으로 개발합니다. 다른 유저에게 배포하는 기능과 클라우드 동기화는 후속 단계에서 고려합니다.

## 수익 기록 원칙

- 실제 순수익은 판매·수령이 확정된 수입에서 실제 지출을 뺀 값입니다.
- 미판매 아이템의 수량과 예상 가치는 실제 메소 수입과 따로 표시합니다.
- 보스 클리어는 결정석 수익으로 즉시 반영하고 드랍 판매는 별도로 기록합니다.
- 기록 당시 단가·수수료·분배 결과를 보존하여 이후 설정 변경이 과거 수익을 바꾸지 않도록 합니다.
- 같은 기록의 반복 조회나 판매 정산이 수입을 중복 생성하지 않도록 합니다.
- 기간 집계는 한국 시간(KST)을 기준으로 하고 과거 기록을 유지합니다.

## 기술 구성 계획

| 영역        | 기술                                            |
| ----------- | ----------------------------------------------- |
| 데스크톱    | Electron                                        |
| 프론트엔드  | React, TypeScript, Tailwind CSS v4              |
| 백엔드      | TypeScript, SQLite (Node.js 내장 `node:sqlite`) |
| 개발 빌드   | electron-vite                                   |
| 테스트      | Vitest                                          |
| 게임 데이터 | NEXON Open API                                  |

현재 의존성은 `package-lock.json`으로 고정합니다. 빌드는 electron-vite 5와 호환되는 Vite 7을 사용합니다. DB는 Electron에 포함된 Node.js의 내장 SQLite를 사용하므로 별도 네이티브 드라이버 재빌드가 필요하지 않습니다.

## 프로젝트 구조

```text
src/
├─ frontend/   # React 화면, 입력 폼, Tailwind 스타일
├─ backend/    # 업무 처리, 수익 계산, DB 저장, 넥슨 API 연동
├─ desktop/    # Electron 창 관리, preload, IPC 연결
└─ shared/     # 호출 계약, DTO, 오류 코드, 입력 검증
```

백엔드는 Electron main 프로세스에서, 프론트엔드는 renderer 프로세스에서 실행합니다. 두 영역은 preload가 제공하는 제한된 API와 IPC를 통해 연결합니다. 앱 정보, 캐릭터 관리, 사냥 회차 관리와 거래 내역 조회 호출이 연결되어 있습니다. 사냥 회차와 연결된 거래는 하나의 DB 트랜잭션으로 저장·수정·삭제합니다.

```text
화면 입력 → preload / IPC → 요청 검증 → 백엔드 서비스 → 계산·DB 저장 → 결과 표시
```

백엔드의 서비스는 업무 흐름을, 저장소(repository)는 SQL 실행을, 계산 함수(domain)는 수익·분배·기간 규칙을 담당합니다. Electron 전용 코드는 desktop 영역에 두어 업무 코드와 분리합니다.

## 실행 안내

Node.js 24 이상과 npm이 필요합니다. Git Bash에서 프로젝트 폴더로 이동해 실행하세요.

```bash
npm ci
npm run dev
```

이미 의존성을 설치했다면 `npm run dev`만 실행하면 됩니다. Electron 창이 열리며, React 코드를 수정하면 개발 화면에 반영됩니다. 종료할 때는 앱 창을 닫고 터미널에서 `Ctrl+C`를 누르세요.

```bash
# 타입 검사
npm run typecheck

# 캐릭터·보스·사냥 저장, 정산과 입력 검증 테스트
npm test

# 타입 검사와 프로덕션 빌드
npm run build

# 빌드한 앱 실행
npm start

# Windows x64 설치 파일 생성
npm run dist:win

# 코드 포맷 검사와 자동 정리
npm run format:check
npm run format
```

PowerShell에서 npm 스크립트 실행이 차단된다면 같은 명령의 `npm`을 `npm.cmd`로 바꾸어 실행할 수 있습니다.

## API와 데이터 보관 계획

**설정 → 넥슨 API 연결**에서 발급받은 키를 입력하고 **API 키 저장**을 누릅니다. 저장·변경은 재시작 없이 다음 요청부터 적용됩니다. 입력칸은 저장 요청 시 비우며 저장된 키를 다시 화면에 표시하지 않습니다. 저장은 키 형식을 확인하며, 실제 유효성은 **API 연결 테스트**로 별도로 확인합니다.

기존 개발용 `.env`도 사용할 수 있습니다. 프로젝트 루트에서 `.env.example`을 `.env`로 복사하고 `NEXON_API_KEY=발급받은키`를 입력합니다. `.env`와 `.env.*`는 Git에서 제외하고, 값이 없는 `.env.example`만 공유합니다. 키 변수에 `VITE_` 접두사를 붙이지 않습니다. 앱은 개발·빌드 미리보기 실행 시 Electron main 프로세스에서만 `.env`를 읽으며, 이 파일을 변경하면 재시작해야 합니다. 설정에서 저장한 키가 우선이며, **저장된 키 삭제** 시 `.env` 키가 있으면 그 키로 돌아갑니다. `.env` 파일 자체는 변경하지 않습니다.

실행 후 **설정 → API 연결 테스트**로 연결을 확인하고, **캐릭터 관리 → 내 캐릭터 불러오기**에서 이름·월드·직업으로 검색합니다. 원하는 캐릭터를 체크한 뒤 **선택한 N개 등록**으로 한 번에 장부에 추가합니다. **검색 결과 전체 선택**은 현재 검색 결과의 미연결 캐릭터만 추가로 체크하며, 검색 조건을 바꿔도 기존 선택은 유지됩니다. **선택 해제**는 전체 선택을 지웁니다. 이미 API에 연결된 캐릭터는 숨김 여부와 함께 표시하고 선택에서 제외합니다. 캐릭터 옆 **정보** 버튼으로 레벨·직업·길드를 별도로 조회할 수 있습니다.

일괄 등록 결과는 신규·이미 등록·실패·미처리 개수로 표시합니다. 성공한 기록은 유지하고 실패·미처리 캐릭터만 체크 상태로 남겨 재시도할 수 있습니다. 기존 같은 이름·월드의 캐릭터는 ID·메모·숨김 상태와 연결 기록을 유지합니다. API 목록에서 미연결 기존 캐릭터도 다시 선택하면 같은 ID에 연결할 수 있습니다. 등록하면 OCID와 레벨·직업·길드·갱신 시각이 저장되며, 캐릭터 카드의 **API 정보 갱신**과 **API 프로필 모두 갱신**으로 최신 정보와 이름·서버를 적용합니다. 캐릭터 관리 화면을 열면 하루 이상 지난 표시 캐릭터의 프로필을 자동 갱신합니다. API 오류 시 기존 프로필을 유지하며 **API 연결 해제**는 연결과 프로필만 지웁니다. 30일 지난 프로필 캐시는 캐릭터 조회 시 정리하고 장부와 OCID는 유지합니다.

API 키 없이도 수동 장부를 사용할 수 있습니다. 설정에 저장한 키는 Electron `safeStorage`로 암호화해 앱 데이터 폴더의 `secrets/nexon-api-key.bin`에 보관하며 장부 DB와 분리합니다. 암호화가 불가능하면 저장을 막고 평문으로 대체하지 않습니다. Windows에서는 OS 사용자 계정으로 보호하므로 다른 PC나 계정에 파일을 복사했을 때에는 키를 다시 입력해야 할 수 있습니다. 기존 개발용 `.env`는 평문 파일이며 패키징한 앱은 이 파일을 읽지 않습니다. 키는 API 상태 응답·로그·빌드에 포함하지 않습니다.

캐릭터와 장부는 앱 데이터 폴더의 `data/maple-roster.sqlite`에 저장됩니다. 같은 이름·월드의 중복 등록을 막으며, 숨김은 데이터를 유지하고 일반 캐릭터 목록에서 제외합니다. 숨긴 캐릭터의 과거 보스·사냥 기록은 계속 조회할 수 있습니다. 삭제는 확인 후 영구 반영됩니다. 보스 프리셋·보스 기록·사냥 기록이 연결된 캐릭터는 삭제할 수 없으며, 숨김을 사용할 수 있습니다. 기존 DB는 실행 시 새 장부 구조로 자동 업데이트하고 사냥 거래 ID·날짜·금액을 유지합니다.

**설정 → 백업과 복원**에서 장부 전체를 JSON 파일로 저장할 수 있습니다. API 키는 제외하며 캐릭터·OCID·프로필·프리셋·보스·사냥·드랍 판매·거래 기록을 보관합니다. 복원할 파일을 선택하면 검증과 기록 수 비교를 거치고, 전체 교체 확인 후 적용합니다. 복원 직전 기존 장부를 앱 데이터 폴더의 `backups`에 자동 저장하며 그 경로를 결과에 표시합니다. 안전 백업을 저장하지 못하거나 DB 저장에 실패하면 기존 장부를 유지합니다. 현재 PC의 API 키는 유지됩니다. 상세 형식과 제한은 [백업과 복원](docs/backup.md)을 참고하세요.

**거래 내역 → CSV 내보내기**로 마지막 조회에 적용한 기간·캐릭터의 거래를 저장할 수 있습니다. 한글을 위한 UTF-8 BOM과 날짜·서버·분류·수입/지출·메소 금액·순수익 변동·원본 ID를 포함합니다. 지출의 순수익 변동은 음수로 기록하여 합산하기 쉽게 했습니다. 데이터가 없으면 헤더만 저장합니다. 사용 방법과 큰 금액의 엑셀 가져오기 안내는 [CSV 내보내기](docs/csv-export.md)를 참고하세요.

사냥 시간·획득 메소·드랍 수량·실제 판매 금액은 직접 기록합니다. 보스 장부의 캐릭터별 **API 클리어 조회**에서 보스·난이도가 일치하는 완료 기록을 확인하고 원하는 보스만 체크해 반영할 수 있습니다. 기존 수동 클리어와 수익은 유지하고 API 미완료로 체크를 해제하지 않습니다. 인원은 장부 설정을 사용하며 수익 반영일은 확인 화면에서 조정할 수 있습니다. 상세 규칙은 [API 보스 클리어](docs/boss-api-sync.md)를 참고하세요.

확인한 공식 스케줄러 명세에 따르면 본인 계정 캐릭터만 조회할 수 있고, 과거 조회는 요청일 기준 최대 14일 전까지 가능합니다. 장기 기록은 앱에 별도로 보존합니다. 자세한 내용은 [넥슨 스케줄러 API](https://openapi.nexon.com/ko/game/maplestory/?id=57)와 [확인한 명세](docs/references/nexon-scheduler.yaml)를 참고하세요.
